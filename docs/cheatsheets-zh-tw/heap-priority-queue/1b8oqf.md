# Scheduling Tasks With Cooldown Intervals — 求解帶冷卻時間的任務最小執行時間

## 問題的本質

給定一個任務陣列（以字母表示）和一個非負整數 `n`（冷卻間隔）。相同的任務必須間隔至少 `n` 個時間單位才能再次執行。在冷卻期間 CPU 會處於閒置狀態。請回傳完成所有任務所需的**最小時間單位數**。

## 核心思路

出現頻率最高的任務決定了整個排程的骨架。根據最頻任務之間產生的冷卻間隙能否被其他任務填滿，整體時間取決於「公式計算結果」與「任務總數」兩者中較大的那個值。

## 思考過程

1. **最頻任務成為瓶頸**：冷卻限制最嚴格的是出現次數最多的任務。這個任務主導了整個排程的長度
2. **排列最頻任務會產生間隙**：設最頻任務的出現次數為 `maxFreq`，將此任務以 `n` 個間隔排列時，任務之間會產生 `(maxFreq - 1)` 個區塊。每個區塊的長度為 `(n + 1)`（1 個任務＋`n` 個冷卻時段）
3. **用其他任務填補間隙**：在每個區塊內的冷卻時段中放入其他任務，以減少閒置時間。若間隙全部填滿，則不會產生閒置
4. **最後一個區塊需特殊處理**：最後一次執行不需要冷卻，因此最後的區塊只包含最頻任務（及同頻率的任務）。設與最頻任務出現次數相同的任務個數為 `maxCount`，則最後區塊的長度為 `maxCount`
5. **用公式計算整體長度**：`(maxFreq - 1) * (n + 1) + maxCount` 可求出以最頻任務為主軸的排程長度
6. **需要與任務總數進行比較**：若間隙全部填滿且仍有多餘任務，則完全不需要閒置，任務總數本身即為答案。因此最終答案為 `Math.max(formulaResult, tasks.length)`

## 前置知識

### 頻率陣列

使用固定大小的陣列來計算每個字母出現次數的技巧。若僅限英文大寫字母，大小為 26 的陣列即可涵蓋所有字母。比 HashMap 更快速且更省記憶體。

```java
int[] freq = new int[26];            // 初始化對應 A〜Z 的 26 個計數器為 0
freq['B' - 'A']++;                   // 將 'B' 的出現次數加 1（索引為 1）
freq['B' - 'A'];                     // 取得 'B' 的出現次數 → 1
```

### Math.max

回傳兩個值中較大者的方法。用於從兩個候選值中選出答案。

```java
Math.max(10, 7);    // → 10（回傳較大者）
Math.max(5, 12);    // → 12
```

### 本題中的區塊結構

設最頻任務為 `A`（出現次數 3）、`n = 2`，則排程具有以下區塊結構：

```
[A _ _] [A _ _] [A]
 區塊1    區塊2   最後
```

`_` 為冷卻時段，可放入其他任務或閒置。最後的區塊不需要冷卻，因此只包含 `A`。

## 複雜度

| | 值 |
|---|---|
| Time | O(k) — 遍歷任務陣列一次，並對固定長度 26 的陣列進行常數次遍歷（k 為任務數） |
| Space | O(1) — 僅使用大小為 26 的固定長度陣列 |

## 程式碼

```java
// 輸入：字元陣列 tasks（每個任務為 'A'〜'Z' 的英文大寫字母）與非負整數 n（冷卻間隔）
// 輸出：以 int 回傳完成所有任務所需的最小時間單位數
public int leastInterval(char[] tasks, int n) {
    // 建立大小為 26 的頻率陣列。freq[0] 對應 'A' 的次數，freq[1] 對應 'B' 的次數
    int[] freq = new int[26];
    // 遍歷 tasks，透過 t - 'A' 將字元轉換為 0〜25 的索引並計數
    for (char t : tasks)
        freq[t - 'A']++;

    // 遍歷 freq 陣列以求出最大出現次數。maxFreq 決定排程的區塊數
    int maxFreq = 0;
    for (int f : freq)
        maxFreq = Math.max(maxFreq, f);

    // 計算出現次數等於 maxFreq 的任務個數。maxCount 為最後區塊中包含的任務數
    int maxCount = 0;
    for (int f : freq)
        if (f == maxFreq) maxCount++;

    // (maxFreq - 1)：需要冷卻的區塊數
    // (n + 1)：每個區塊的長度（1 個任務＋n 個冷卻時段）
    // maxCount：最後區塊的長度（僅包含最頻任務及同頻率的任務）
    int formulaResult =
        (maxFreq - 1) * (n + 1)
        + maxCount;

    // formulaResult 為因冷卻產生閒置時的長度
    // tasks.length 為完全不需要閒置時（間隙全部填滿且有多餘任務）的長度
    // 兩者中較大的值即為正確答案
    return Math.max(formulaResult,
        tasks.length);
}
```
