# Finding the Minimum Time to Swim Across a Grid — 求解游過網格的最短時間

## 問題的本質

給定一個 n×n 的網格，每個儲存格包含一個從 0 到 n²-1 的唯一海拔值。只有當目前時刻**大於或等於兩個儲存格的海拔值**時，才能從一個儲存格游向相鄰儲存格（上下左右）。求從左上角 (0,0) 到達右下角 (n-1,n-1) 所需的**最小時刻**。起始時刻為 grid[0][0] 的值。

## 核心思路

路徑上所經過儲存格的海拔**最大值**即為該路徑所需的時刻。使用最小堆按照「目前可到達的儲存格中，所需時刻最小的儲存格」的順序進行探索，則首次到達終點時的時刻即為最佳解。

## 思考過程

1. **重新詮釋移動條件**：從儲存格 A 移動到儲存格 B 需要「時刻 ≥ max(A, B)」。也就是說，從起點到終點的整條路徑所需的時刻等於「路徑上所有儲存格的海拔最大值」。因此問題可歸結為「找到一條路徑，使其上的最大海拔最小化」
2. **發現與最短路徑問題的相似性**：普通的 Dijkstra 演算法最小化「路徑上邊權重的總和」，而本問題最小化「路徑上儲存格海拔的最大值」。只需將總和替換為最大值，即可直接套用 Dijkstra 的框架
3. **使用優先佇列從所需時刻最小的儲存格開始展開**：將儲存格以「到達該儲存格所需的時刻」為鍵存入最小堆（PriorityQueue）。始終從所需時刻最小的儲存格開始展開，可保證每個儲存格首次被取出時的時刻即為最佳時刻
4. **計算到達相鄰儲存格的所需時刻**：當目前儲存格 (r,c) 的所需時刻為 `time` 時，到達相鄰儲存格 (nr,nc) 的所需時刻為 `Math.max(time, grid[nr][nc])`。這是因為「到目前為止路徑上的最大海拔」與「下一個儲存格的海拔」中較大的一方即為新路徑的所需時刻
5. **使用已訪問管理防止重複處理**：從最小堆中取出的儲存格，其最佳時刻在該時刻點已確定。使用已訪問陣列 `vis` 進行標記，避免重複處理同一個儲存格。這與 Dijkstra 中已確定節點的概念相同
6. **到達終點時立即返回**：當從堆中取出的儲存格為 (n-1, n-1) 時，該 `time` 即為最小時刻。由於最小堆按照時刻從小到大的順序進行處理，因此首次到達終點時即為最佳解

## 前置知識

### 什麼是 PriorityQueue（最小堆）

PriorityQueue 是一種可按照優先順序取出元素的資料結構。預設情況下，最小值具有最高優先順序。插入和取出操作的時間複雜度均為 O(log n)。在 Dijkstra 演算法中，使用它來高效地執行「從未確定的節點中選取成本最小的節點」的操作。

```java
// 建立按照 int[] 第 0 個元素升序排列的最小堆
PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[0] - b[0]);
pq.offer(new int[]{5, 0, 0});   // 新增元素（O(log n)）
pq.offer(new int[]{3, 1, 0});   // 新增元素
int[] min = pq.poll();          // 取出並刪除最小元素 → {3, 1, 0}
boolean empty = pq.isEmpty();   // 判斷佇列是否為空 → false
```

### 什麼是 Dijkstra 演算法的變形

普通的 Dijkstra 演算法最小化邊權重的**總和**，而本問題最小化路徑上海拔的**最大值**。只需將距離更新公式從 `dist[next] = dist[cur] + weight` 改為 `dist[next] = max(dist[cur], grid[next])`，Dijkstra 的正確性（從最小堆取出時最佳值已確定的性質）即可完整保持。

### 四方向相鄰儲存格探索

網格上儲存格 (r,c) 的上下左右相鄰儲存格，可透過加上方向向量 `{{0,1},{0,-1},{1,0},{-1,0}}` 來列舉。執行範圍外檢查（0 ≤ nr < n 且 0 ≤ nc < n），僅處理有效的儲存格。

```java
int[][] dir = {{0,1},{0,-1},{1,0},{-1,0}};  // 右、左、下、上四個方向
for (int[] d : dir) {
    int nr = r + d[0];  // 相鄰儲存格的列索引
    int nc = c + d[1];  // 相鄰儲存格的行索引
    if (nr >= 0 && nr < n && nc >= 0 && nc < n) {
        // (nr, nc) 是有效的相鄰儲存格
    }
}
```

## 計算複雜度

| | 值 |
|---|---|
| Time | O(n² log n) — 對 n² 個儲存格各最多進行一次堆的插入與取出操作。每次堆操作的時間複雜度為 O(log n²) = O(log n) |
| Space | O(n²) — 已訪問陣列和堆各最多保存 n² 個儲存格 |

## 程式碼

```java
// 輸入：n×n 的整數陣列 grid（每個儲存格包含 0 到 n²-1 的唯一海拔值）
// 輸出：以 int 返回從左上角 (0,0) 到達右下角 (n-1,n-1) 所需的最小時刻
int swimInWater(int[][] grid) {
    int n = grid.length;
    // 管理各儲存格最佳時刻是否已確定的已訪問陣列（vis[r][c] = true 表示已確定）
    boolean[][] vis = new boolean[n][n];
    // 按照所需時刻從小到大取出的最小堆（元素：{時刻, 行, 列}）
    // 比較函式 (a,b)->a[0]-b[0] 使其按第 0 個元素（所需時刻）升序取出
    PriorityQueue<int[]> pq =
        new PriorityQueue<>(
            (a, b) -> a[0] - b[0]);
    // 將起點加入堆中，並標記為已訪問
    // 第 0 個元素為所需時刻，第 1 個元素為行，第 2 個元素為列
    pq.offer(new int[]
        {grid[0][0], 0, 0});
    vis[0][0] = true;
    // 上下左右四個方向向量
    int[][] dir =
        {{0,1},{0,-1},{1,0},{-1,0}};
    while (!pq.isEmpty()) {
        // 取出所需時刻最小的儲存格（根據最小堆的性質，此時刻點的最佳時刻已確定）
        int[] cur = pq.poll();
        int time = cur[0];
        int r = cur[1], c = cur[2];
        // 若到達終點，則該時刻即為最佳解（因為按照最小時刻順序處理，首次到達即為最佳）
        if (r == n-1 && c == n-1)
            return time;
        // 探索四個方向的相鄰儲存格
        for (int[] d : dir) {
            int nr = r+d[0];
            int nc = c+d[1];
            // 僅處理範圍內且未訪問的儲存格
            if (nr >= 0 && nr < n
                && nc >= 0 && nc < n
                && !vis[nr][nc]) {
                // 注意：在加入堆的時刻點標記為已訪問，以防止同一儲存格被多次加入堆中
                vis[nr][nc] = true;
                // 路徑上的最大海拔即為所需時刻（取「到目前為止的最大海拔」與「下一個儲存格的海拔」中的較大值）
                int nt = Math.max(
                    time,grid[nr][nc]);
                pq.offer(new int[]
                    {nt, nr, nc});
            }
        }
    }
    // 根據問題的約束條件，網格是連通的，因此不會到達此處
    return -1;
}
```
