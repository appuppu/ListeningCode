# Reconstructing a Flight Itinerary — 從航空機票重建字典序最小的行程

## 問題的本質

給定一個以出發機場和到達機場配對表示的航空機票列表。從JFK出發，將所有機票恰好使用一次，重建完整的行程。若存在多個有效行程，則返回字典序最小的行程。

## 核心思路

這是一個恰好經過所有邊（機票）一次的歐拉路徑問題。若以PriorityQueue管理各機場的目的地，則可自動保證字典序最小；使用Hierholzer演算法從後方構建行程，即可正確處理死路的情況。

## 思考過程

1. **將所有機票恰好使用一次 = 歐拉路徑**：每張機票是有向圖的一條邊，求恰好經過所有邊一次的路徑，可歸結為歐拉路徑（Eulerian Path）問題
2. **保證字典序最小需要排序**：當某機場有多個目的地時，需優先選擇字典序較小的目的地。將各機場的目的地存入PriorityQueue（最小堆），只需呼叫`poll()`即可始終取得字典序最小的目的地
3. **單純的貪心法無法處理死路**：若總是選擇字典序最小的目的地，可能在尚有未使用的邊時就先到達死路。例如有JFK→A→JFK→B的機票時，從JFK先選A可以走A→JFK→B，但若先選B則會在B處遇到死路
4. **使用Hierholzer演算法從後方構建**：在DFS中，當某節點已無可前往的目的地（到達死路）時，將該節點添加到結果列表的**開頭**。如此一來，死路會被放置在行程的末尾，其餘的邊在遞迴回溯時會以正確的順序被添加到開頭
5. **遞迴DFS的運作方式**：從當前節點透過PriorityQueue取出字典序最小的目的地，遞迴地進行DFS。當無目的地可前往時，將當前節點添加到結果列表的開頭。使用LinkedList的`addFirst`可以O(1)完成開頭插入
6. **最終返回的結果**：所有DFS完成後，直接返回結果列表（LinkedList）。列表中儲存了從JFK開始的字典序最小行程

## 前提知識

### PriorityQueue（優先佇列）是什麼

一種在添加元素時自動排序、取出時始終取得最小元素的資料結構。內部以堆實現，添加和取出的時間複雜度均為O(log n)。

```java
PriorityQueue<String> pq = new PriorityQueue<>();  // 以字串的自然順序（字典序）建立最小堆
pq.offer("SFO");       // 添加"SFO"
pq.offer("ATL");       // 添加"ATL"
pq.poll();             // 取出並刪除最小元素"ATL" → "ATL"
pq.isEmpty();          // 以boolean返回佇列是否為空 → false（"SFO"仍在佇列中）
```

### computeIfAbsent 是什麼

當HashMap中不存在指定的鍵時，才以指定的函數生成值並註冊，然後返回該值的方法。若鍵已存在，則直接返回既有的值。可將`get`後`null`檢查再`put`的三個步驟合為一行。

```java
Map<String, PriorityQueue<String>> graph = new HashMap<>();
// 若"JFK"鍵不存在，則建立新的PriorityQueue並註冊，然後返回該PriorityQueue
graph.computeIfAbsent("JFK", k -> new PriorityQueue<>()).offer("SFO");
// "JFK"鍵已存在，因此返回既有的PriorityQueue（不會重新建立）
graph.computeIfAbsent("JFK", k -> new PriorityQueue<>()).offer("ATL");
```

### LinkedList 的 addFirst 是什麼

以O(1)將元素添加到列表開頭的方法。與一般的`add`（末尾添加）不同，無需將既有元素向後移動即可插入到開頭。在Hierholzer演算法中用於以逆序構建結果。

```java
LinkedList<String> result = new LinkedList<>();
result.addFirst("JFK");   // result: ["JFK"]
result.addFirst("ATL");   // result: ["ATL", "JFK"]
result.addFirst("SFO");   // result: ["SFO", "ATL", "JFK"]
```

### Hierholzer演算法是什麼

用於求歐拉路徑（恰好經過所有邊一次的路徑）的演算法。在DFS中逐步消耗邊並前進，到達死路的節點會被添加到結果的開頭。在所有邊被使用完畢後，結果列表中即以正確的順序儲存了歐拉路徑。此演算法能自然地將死路放置在行程末尾，因此非常適合本問題。

## 計算量

| | 值 |
|---|---|
| Time | O(E log E) — 將每張機票（邊）添加到PriorityQueue及從中取出時，每次需要O(log E)的成本 |
| Space | O(V + E) — 圖的鄰接列表儲存所有的邊，遞迴堆疊的深度最多為邊的數量 |

## 程式碼

```java
// 輸入：航空機票列表 tickets（每張機票為 [出發機場, 到達機場] 的字串配對）
// 輸出：以 List<String> 返回從JFK開始的字典序最小行程
public List<String> findItinerary(List<List<String>> tickets) {
    // 鍵=出發機場，值=以字典序管理到達機場的PriorityQueue
    // 使用PriorityQueue，取出時始終可獲得字典序最小的目的地
    Map<String, PriorityQueue<String>> graph = new HashMap<>();

    // 從所有機票構建圖
    // 透過computeIfAbsent，若src鍵為首次出現則建立新的PriorityQueue，若已存在則直接取得
    for (List<String> t : tickets) {
        graph.computeIfAbsent(t.get(0), k -> new PriorityQueue<>())
             .offer(t.get(1));
    }

    // 儲存結果的LinkedList（使用addFirst以O(1)進行開頭插入）
    LinkedList<String> result = new LinkedList<>();

    // 從JFK開始DFS
    dfs("JFK", graph, result);
    return result;
}

void dfs(String curr,
          Map<String, PriorityQueue<String>> graph,
          LinkedList<String> result) {
    // 取得從當前機場可前往的目的地PriorityQueue
    PriorityQueue<String> dests = graph.get(curr);

    // 在有目的地的期間，取出字典序最小的目的地並進行DFS
    // 注意：poll()會刪除元素，因此不會經過同一條邊（機票）兩次
    while (dests != null && !dests.isEmpty()) {
        dfs(dests.poll(), graph, result);
    }

    // 到達死路時，將當前機場添加到結果列表的開頭
    // 透過添加到開頭，死路節點會被放置在行程的末尾側，
    // 之後添加的節點會被正確地放置在行程的前方
    result.addFirst(curr);
}
```
