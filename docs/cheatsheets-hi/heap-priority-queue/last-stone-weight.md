# Simulating a Last Stone Weight Game — दो-दो पत्थर टकराकर अंत में बचे पत्थर का वज़न ज्ञात करना

## समस्या का सार

एक पूर्णांक सरणी `stones` दी गई है। हर बार **सबसे भारी 2 पत्थर** निकालकर उन्हें टकराया जाता है। यदि दोनों पत्थरों का वज़न बराबर है तो दोनों नष्ट हो जाते हैं, और यदि भिन्न है तो हल्का पत्थर नष्ट हो जाता है और भारे पत्थर का वज़न अंतर के बराबर हो जाता है। यह प्रक्रिया तब तक दोहराई जाती है जब तक 1 या उससे कम पत्थर शेष रहे, और अंत में बचे पत्थर का वज़न लौटाना है। यदि कोई पत्थर नहीं बचता तो 0 लौटाना है।

## मूल विचार

हर बार "सबसे भारे 2 पत्थर" को कुशलतापूर्वक निकालने की आवश्यकता है। अधिकतम हीप (Max-Heap) का उपयोग करने पर अधिकतम मान को O(log n) में निकाला जा सकता है, इसलिए दोबारा सॉर्ट किए बिना हमेशा सबसे भारे 2 पत्थर प्राप्त किए जा सकते हैं।

## विचार प्रक्रिया

1. **हर बार की प्रक्रिया में 2 अधिकतम मान चाहिए**: पत्थर टकराने के नियम के अनुसार, हमेशा सबसे भारे 2 पत्थर चुने जाते हैं। अर्थात यह "वर्तमान समूह से अधिकतम मान को 2 बार निकालने" की प्रक्रिया को दोहराने की समस्या है
2. **अधिकतम मान को तेज़ी से निकालना आवश्यक है**: सरणी को हर बार सॉर्ट करने पर प्रत्येक चरण में O(n log n) लगता है। अधिकतम हीप का उपयोग करने पर अधिकतम मान निकालना O(log n) में और तत्व सम्मिलित करना भी O(log n) में हो जाता है
3. **Java के PriorityQueue को Max-Heap के रूप में उपयोग करना**: Java का PriorityQueue डिफ़ॉल्ट रूप से Min-Heap (न्यूनतम मान शीर्ष पर) होता है। `Collections.reverseOrder()` को comparator के रूप में देने पर यह Max-Heap के रूप में कार्य करता है जिसमें अधिकतम मान शीर्ष पर आता है
4. **सभी पत्थरों को हीप में डालना**: सरणी `stones` के सभी तत्वों को PriorityQueue में जोड़ा जाता है। इससे हीप अधिकतम मान प्रबंधित करने के लिए तैयार हो जाता है
5. **जब तक 2 या अधिक पत्थर हैं, टकराने की प्रक्रिया दोहराना**: हीप से `poll()` द्वारा अधिकतम मान 2 बार निकाला जाता है, और यदि अंतर 0 नहीं है तो अंतर को `add()` से हीप में वापस डाला जाता है। यदि अंतर 0 है तो कुछ भी वापस नहीं डाला जाता (दोनों नष्ट हो जाते हैं)
6. **अंतिम स्थिति की जाँच करके लौटाना**: लूप समाप्त होने के बाद, यदि हीप खाली है तो सभी पत्थर नष्ट हो गए हैं इसलिए 0 लौटाया जाता है। यदि हीप में 1 पत्थर शेष है तो उसका वज़न `poll()` से निकालकर लौटाया जाता है

## पूर्वापेक्षित ज्ञान

### PriorityQueue (प्राथमिकता कतार) क्या है

यह एक डेटा संरचना है जिसमें तत्व जोड़ने पर आंतरिक रूप से स्वचालित क्रम प्रबंधित होता है, और `poll()` से हमेशा सबसे अधिक प्राथमिकता वाला तत्व निकाला जा सकता है। आंतरिक कार्यान्वयन हीप (बाइनरी हीप) है, और जोड़ना तथा निकालना दोनों O(log n) में होते हैं।

```java
// डिफ़ॉल्ट Min-Heap है (न्यूनतम मान शीर्ष पर होता है)
PriorityQueue<Integer> minHeap = new PriorityQueue<>();
minHeap.add(5);       // तत्व 5 को जोड़ता है
minHeap.add(2);       // तत्व 2 को जोड़ता है
minHeap.poll();       // न्यूनतम मान 2 को निकालकर लौटाता है
minHeap.size();       // वर्तमान तत्वों की संख्या लौटाता है → 1
minHeap.isEmpty();    // कतार खाली है या नहीं boolean में लौटाता है → false
```

### Collections.reverseOrder() क्या है

यह PriorityQueue के constructor में दिया जाने वाला comparator है, जो डिफ़ॉल्ट आरोही क्रम (Min-Heap) को अवरोही क्रम (Max-Heap) में उलट देता है। इससे `poll()` अधिकतम मान लौटाने लगता है।

```java
// Max-Heap (अधिकतम मान शीर्ष पर) बनाता है
PriorityQueue<Integer> maxHeap =
    new PriorityQueue<>(Collections.reverseOrder());
maxHeap.add(3);       // तत्व 3 को जोड़ता है
maxHeap.add(7);       // तत्व 7 को जोड़ता है
maxHeap.add(1);       // तत्व 1 को जोड़ता है
maxHeap.poll();       // अधिकतम मान 7 को निकालकर लौटाता है
maxHeap.poll();       // अगला अधिकतम मान 3 को निकालकर लौटाता है
```

### Max-Heap की कार्यप्रणाली का चित्रण

stones = [2, 7, 4, 1, 8, 1] के मामले में:
- हीप में सभी तत्व जोड़ने पर, आंतरिक रूप से `[8, 7, 4, 1, 2, 1]` के रूप में प्रबंधित होता है
- `poll()` → 8 को निकालता है। हीप `[7, 4, 2, 1, 1]` में पुनर्गठित होता है
- `poll()` → 7 को निकालता है। 8 - 7 = 1 को `add()` से हीप में वापस डालता है

## गणना जटिलता

| | मान |
|---|---|
| Time | O(n log n) — अधिकतम n बार टकराने की प्रक्रिया होती है, और प्रत्येक प्रक्रिया में हीप से निकालने व जोड़ने में O(log n) लगता है |
| Space | O(n) — हीप में अधिकतम n पत्थर संग्रहीत होते हैं |

## कोड

```java
// इनपुट: पूर्णांक सरणी stones (प्रत्येक तत्व पत्थर का वज़न है)
// आउटपुट: अंत में बचे पत्थर का वज़न int के रूप में लौटाता है। यदि कोई पत्थर नहीं बचता तो 0 लौटाता है
public int lastStoneWeight(int[] stones) {
    // Collections.reverseOrder() को comparator में निर्दिष्ट करके, poll() अधिकतम मान लौटाने वाला Max-Heap बनाता है
    PriorityQueue<Integer> pq =
        new PriorityQueue<>(Collections.reverseOrder());

    // सभी पत्थरों को हीप में जोड़ता है। पूर्ण होने पर हीप अधिकतम मान को शीर्ष पर प्रबंधित करने की स्थिति में होता है
    for (int s : stones) pq.add(s);

    // जब तक 2 या अधिक पत्थर हैं, सबसे भारे 2 पत्थरों को टकराने की प्रक्रिया दोहराता है
    while (pq.size() >= 2) {
        // poll() को 2 बार बुलाकर सबसे भारा और अगला सबसे भारा पत्थर निकालता है
        // Max-Heap होने के कारण a >= b हमेशा सत्य रहता है
        int a = pq.poll();
        int b = pq.poll();

        // यदि वज़न भिन्न है तो अंतर का पत्थर हीप में वापस डालता है। यदि बराबर है तो दोनों नष्ट होते हैं इसलिए कुछ नहीं डालता
        if (a != b) pq.add(a - b);
    }

    // यदि हीप खाली है तो सभी पत्थर नष्ट हो गए इसलिए 0, अन्यथा शेष पत्थर का वज़न लौटाता है
    return pq.isEmpty() ? 0 : pq.poll();
}
```
