# Counting Ways to Assign Signs to Reach a Target Sum — चिह्न निर्धारण द्वारा लक्ष्य योग प्राप्त करने के तरीकों की गणना

## समस्या का सार

एक पूर्णांक सरणी `nums` और एक पूर्णांक `target` दिया गया है। `nums` के प्रत्येक तत्व को `+` या `-` चिह्न निर्दिष्ट करके, सभी तत्वों का योग `target` के बराबर बनाने वाले संयोजनों की कुल संख्या लौटानी है।

## मूल विचार

प्रत्येक तत्व को `+` या `-` निर्दिष्ट करने की समस्या, सरणी को "धनात्मक चिह्न समूह (P)" और "ऋणात्मक चिह्न समूह (N)" में विभाजित करने की समस्या के समान है। P - N = target और P + N = totalSum से P = (target + totalSum) / 2 प्राप्त होता है, इसलिए समस्या को "योग P बनाने वाले उपसमुच्चयों की संख्या गिनना" अर्थात उपसमुच्चय योग समस्या में रूपांतरित किया जा सकता है।

## विचार प्रक्रिया

1. **चिह्न निर्धारण को समुच्चय विभाजन के रूप में समझना**: प्रत्येक तत्व को `+` लगाने पर उनका योग P और `-` लगाने पर उनका योग N मानें, तो P - N = target सिद्ध होता है। साथ ही P + N = totalSum (सभी तत्वों का योग) भी सिद्ध होता है। इन दोनों समीकरणों को हल करने पर P = (target + totalSum) / 2 प्राप्त होता है
2. **हल न होने की शर्तों को पहले बाहर करना**: यदि P = (target + totalSum) / 2 पूर्णांक नहीं बनता (अर्थात `(target + totalSum)` विषम है), तो कोई वैध विभाजन संभव नहीं है। साथ ही यदि `|target|` का मान `totalSum` से अधिक है तो भी कोई हल नहीं है। इन शर्तों की पहले जाँच करके 0 लौटाना चाहिए
3. **उपसमुच्चय योग समस्या के रूप में DP से हल करना**: "सरणी `nums` से तत्व चुनकर योग `subsetSum` (= P) बनाने वाले संयोजनों की संख्या" एक प्रामाणिक उपसमुच्चय योग गणना समस्या है। DP सरणी `dp[j]` को "योग j बनाने वाले उपसमुच्चयों की संख्या" के रूप में परिभाषित करके, प्रत्येक तत्व के लिए अद्यतन करना है
4. **1-आयामी DP सरणी से स्थान का अनुकूलन करना**: 2-आयामी तालिका के बजाय, 1-आयामी सरणी `dp[0..subsetSum]` बनाकर, प्रत्येक तत्व `num` के लिए `j` को `subsetSum` से `num` तक उल्टे क्रम में चलाकर `dp[j] += dp[j - num]` से अद्यतन करना है। उल्टे क्रम में चलाने का कारण यह है कि एक ही तत्व को कई बार उपयोग करने से रोका जा सके
5. **प्रारंभिक शर्त निर्धारित करना**: `dp[0] = 1` सेट करना है। इसका अर्थ है "कुछ भी न चुनकर योग 0 बनाने का 1 तरीका है"
6. **अंतिम परिणाम**: सभी तत्वों को संसाधित करने के बाद `dp[subsetSum]` का मान, योग `subsetSum` बनाने वाले उपसमुच्चयों की संख्या है, अर्थात मूल समस्या का उत्तर है

## पूर्वापेक्षित ज्ञान

### उपसमुच्चय योग समस्या (Subset Sum Problem) क्या है

दिए गए समुच्चय से तत्व चुनकर, उनका योग किसी निश्चित मान के बराबर बनाने वाले संयोजन ज्ञात करने की समस्या है। यह नैपसैक समस्या का एक प्रकार है और DP से कुशलतापूर्वक हल की जा सकती है।

### 1-आयामी DP सरणी द्वारा उपसमुच्चय गणना

`dp[j]` "योग j बनाने वाले उपसमुच्चयों की संख्या" को दर्शाता है। प्रत्येक तत्व `num` के लिए, `dp[j] += dp[j - num]` से अद्यतन करना है।

```java
int[] dp = new int[targetSum + 1]; // dp[j] = योग j बनाने वाले संयोजनों की संख्या
dp[0] = 1;                         // योग 0 बनाने का 1 तरीका है (कुछ भी न चुनना)
dp[j] += dp[j - num];              // num का उपयोग करके j बनाना = num के बिना j-num बनाने के तरीकों की संख्या जोड़ना
```

### उल्टे क्रम के लूप का कारण

आंतरिक लूप को `subsetSum` से `num` तक उल्टे क्रम में चलाना है। यदि सीधे क्रम में चलाएँ तो एक ही तत्व `num` को उसी पुनरावृत्ति में कई बार जोड़ दिया जाएगा। उल्टे क्रम से चलाने पर, प्रत्येक तत्व को "चुनना या न चुनना" की 0-1 नैपसैक बाधा पूरी होती है।

```java
// उल्टे क्रम का लूप: प्रत्येक तत्व को अधिकतम 1 बार उपयोग करना (0-1 नैपसैक)
for (int j = subsetSum; j >= num; j--) {
    dp[j] += dp[j - num];
}
```

## गणना जटिलता

| | मान |
|---|---|
| Time | O(n × subsetSum) — प्रत्येक तत्व के लिए DP सरणी को एक बार चलाना |
| Space | O(subsetSum) — केवल 1-आयामी DP सरणी का उपयोग करना |

## कोड

```java
// इनपुट: पूर्णांक सरणी nums और पूर्णांक target
// आउटपुट: प्रत्येक तत्व को +/- निर्दिष्ट करके योग target बनाने वाले संयोजनों की संख्या int में लौटाना
public int findTargetSumWays(int[] nums, int target) {
    // सरणी nums के सभी तत्वों का योग गणना करके चर totalSum में संग्रहीत करना
    int totalSum = 0;
    for (int num : nums) {
        totalSum += num;
    }

    // हल न होने की शर्तों की जाँच करना
    // यदि (target + totalSum) विषम है, तो P = (target + totalSum) / 2 पूर्णांक नहीं बनता,
    // पूर्णांक संख्या के तत्वों से बने उपसमुच्चय से यह प्राप्त नहीं हो सकता इसलिए 0 लौटाना
    // यदि |target| का मान totalSum से अधिक है, तो किसी भी चिह्न निर्धारण से target तक नहीं पहुँचा जा सकता इसलिए 0 लौटाना
    if ((target + totalSum) % 2 != 0
        || Math.abs(target) > totalSum)
        return 0;

    // धनात्मक चिह्न समूह का योग मान ज्ञात करना। इसके बाद की प्रक्रिया में यही लक्ष्य मान होगा
    int subsetSum = (target + totalSum) / 2;

    // dp[j] = nums के तत्वों को चुनकर योग j बनाने वाले संयोजनों की संख्या
    int[] dp = new int[subsetSum + 1];
    // आधार स्थिति: कुछ भी न चुनकर योग 0 बनाने का 1 तरीका है
    dp[0] = 1;

    // बाहरी लूप: सरणी nums के प्रत्येक तत्व को आरंभ से अंत तक क्रम में चलाना
    for (int num : nums) {
        // आंतरिक लूप: subsetSum से num तक उल्टे क्रम में चलाना
        // उल्टे क्रम का कारण: एक ही num को उसी पुनरावृत्ति में कई बार उपयोग करने से रोकना (0-1 नैपसैक बाधा)
        for (int j = subsetSum; j >= num; j--) {
            // num के बिना योग j - num बनाने के तरीकों की संख्या को, num का उपयोग करके योग j बनाने के तरीकों की संख्या में जोड़ना
            dp[j] += dp[j - num];
        }
    }

    // dp[subsetSum] योग subsetSum बनाने वाले उपसमुच्चयों की संख्या है, अर्थात मूल समस्या में चिह्न निर्धारण के कुल तरीकों की संख्या है
    return dp[subsetSum];
}
```
