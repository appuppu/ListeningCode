# Maximizing Stock Profit With a Cooldown Period — कूलडाउन अवधि के साथ शेयर ट्रेडिंग में अधिकतम लाभ प्राप्त करना

## समस्या का सार

शेयर की कीमतों की एक सरणी `prices` दी गई है। प्रत्येक इंडेक्स एक दिन को दर्शाता है। शेयर को कई बार खरीदा और बेचा जा सकता है, लेकिन बेचने के अगले दिन **कूलडाउन** के रूप में कोई लेनदेन नहीं किया जा सकता। इस प्रतिबंध के अंतर्गत प्राप्त होने वाला **अधिकतम लाभ** लौटाना है।

## मूल विचार

प्रत्येक दिन की स्थिति को "शेयर धारित (hold)", "बिक्री के तुरंत बाद (sold)", और "विश्राम (rest)" इन तीन श्रेणियों में वर्गीकृत किया जाता है, और पिछले दिन की 3 स्थितियों से आज की 3 स्थितियों में संक्रमण परिभाषित किया जाता है। प्रत्येक दिन केवल पिछले दिन पर निर्भर करता है, इसलिए सरणी के बजाय केवल 3 चर से स्थिति प्रबंधित की जा सकती है।

## विचार प्रक्रिया

1. **प्रत्येक दिन की 3 स्थितियाँ होती हैं**: किसी दिन के अंत में, हम "शेयर धारित किए हुए हैं (hold)", "उस दिन बेचा (sold)", या "कुछ नहीं किया (rest)" इनमें से किसी एक स्थिति में होते हैं। ये 3 स्थितियाँ सभी मामलों को कवर करती हैं
2. **स्थितियों के बीच संक्रमण परिभाषित करना**: hold "पिछले दिन भी hold था और कुछ नहीं किया" या "पिछले दिन rest था और आज खरीदा" में से बड़ा मान है। sold "पिछले दिन hold था और आज बेचा" है। rest "पिछले दिन भी rest था और कुछ नहीं किया" या "पिछले दिन sold था और कूलडाउन समाप्त हुआ" में से बड़ा मान है। कूलडाउन का प्रतिबंध "sold के अगले दिन hold में संक्रमण नहीं हो सकता" इस नियम से स्वाभाविक रूप से व्यक्त होता है
3. **प्रारंभिक स्थिति सेट करना**: दिन 0 पर खरीदने पर hold = -prices[0] (लाभ ऋणात्मक होता है)। दिन 0 पर बेचना या विश्राम करना अभी संभव नहीं है, इसलिए sold = Integer.MIN_VALUE (यह स्थिति अप्राप्त होने को दर्शाता है), rest = 0 (कुछ नहीं करने पर लाभ 0 है) सेट किया जाता है
4. **प्रत्येक दिन केवल पिछले दिन की स्थिति पर निर्भर करता है**: संक्रमण सूत्र देखने पर, आज की प्रत्येक स्थिति केवल पिछले दिन की 3 स्थितियों से गणना की जा सकती है। अर्थात सभी दिनों के लिए सरणी रखने की आवश्यकता नहीं है, केवल 3 चर को प्रतिदिन अपडेट करना पर्याप्त है
5. **एक साथ अपडेट करना आवश्यक है**: आज के hold, sold, rest सभी पिछले दिन के मानों से गणना किए जाते हैं, इसलिए नए मानों को अस्थायी चर में संग्रहित करके, फिर एक साथ पिछले दिन के चर को अधिलेखित किया जाता है। क्रमिक रूप से अधिलेखित करने पर, गणना में उपयोग होने वाले पिछले दिन के मान खो जाते हैं
6. **अंतिम रूप से लौटाया जाने वाला मान**: अंतिम दिन शेयर धारित रखकर समाप्त करना इष्टतम नहीं है, इसलिए prevSold और prevRest में से बड़ा मान अधिकतम लाभ है

## पूर्वापेक्षित ज्ञान

### स्टेट मशीन (State Machine) क्या है

सीमित संख्या में स्थितियों और स्थितियों के बीच संक्रमण नियमों से बना एक मॉडल। प्रत्येक समय बिंदु पर निश्चित रूप से एक स्थिति में होता है, और इनपुट के अनुसार दूसरी स्थिति में संक्रमण होता है। इस समस्या में hold / sold / rest की 3 स्थितियों वाली स्टेट मशीन के रूप में लेनदेन को मॉडल किया जाता है।

```
rest ---(खरीदना)---> hold
hold ---(बेचना)---> sold
sold ---(प्रतीक्षा करना)---> rest（कूलडाउन）
hold ---(बनाए रखना)---> hold
rest ---(बनाए रखना)---> rest
```

### Math.max क्या है

दो पूर्णांकों में से बड़ा मान लौटाने वाला मेथड। स्थिति संक्रमण में एकाधिक विकल्प होने पर, अधिक लाभ वाले विकल्प को चुनने के लिए इसका उपयोग किया जाता है।

```java
Math.max(3, 7);    // → 7（बड़ा मान लौटाता है）
Math.max(-5, -2);  // → -2（ऋणात्मक संख्याओं में भी बड़ा मान लौटाता है）
```

### Integer.MIN_VALUE क्या है

Java के int प्रकार का न्यूनतम मान (-2,147,483,648)। "इस स्थिति तक अभी पहुँचा नहीं गया है" यह दर्शाने के लिए इसका उपयोग किया जाता है। किसी भी मान से तुलना करने पर Math.max द्वारा यह चुना नहीं जाता, इसलिए अप्राप्त स्थिति को सुरक्षित रूप से अनदेखा किया जा सकता है।

```java
int x = Integer.MIN_VALUE;  // अभी अप्राप्त स्थिति को दर्शाता है
Math.max(x, 0);             // → 0（अप्राप्त स्थिति नहीं चुनी जाती）
```

## कम्प्यूटेशनल जटिलता

| | मान |
|---|---|
| Time | O(n) — सरणी को केवल एक बार स्कैन करना पर्याप्त है |
| Space | O(1) — केवल 3 चर से स्थिति प्रबंधित की जाती है |

## कोड

```java
// इनपुट: पूर्णांक सरणी prices（प्रत्येक तत्व उस दिन का शेयर मूल्य है）
// आउटपुट: कूलडाउन प्रतिबंध के साथ प्राप्त होने वाला अधिकतम लाभ int के रूप में लौटाता है
public int maxProfit(int[] prices) {
    int n = prices.length;
    // शेयर खरीदने-बेचने के लिए कम से कम 2 दिन आवश्यक हैं। n < 2 होने पर लेनदेन संभव नहीं है इसलिए 0 लौटाता है
    if (n < 2) return 0;

    // दिन 0 की प्रत्येक स्थिति को प्रारंभ करना
    int prevHold = -prices[0];          // दिन 0 पर खरीदने की स्थिति में लाभ（व्यय होने के कारण ऋणात्मक）
    int prevSold = Integer.MIN_VALUE;   // दिन 0 पर बेचना असंभव है（अप्राप्त स्थिति को दर्शाता है）
    int prevRest = 0;                   // कुछ नहीं करने पर लाभ 0 है

    for (int i = 1; i < n; i++) {
        // पिछले दिन की 3 स्थितियों से आज की 3 स्थितियों की गणना करना
        // newHold: "पिछले दिन भी धारित था（prevHold）" या "पिछले दिन विश्राम था और आज खरीदा（prevRest - prices[i]）" में से बड़ा मान
        // ध्यान दें: "पिछले दिन sold था और आज खरीदना" विकल्प में नहीं है। यही कूलडाउन प्रतिबंध को व्यक्त करता है
        int newHold = Math.max(prevHold,
            prevRest - prices[i]);

        // newSold: धारित शेयर को आज बेचना। sell केवल hold से संक्रमित हो सकता है इसलिए Math.max आवश्यक नहीं है
        int newSold = prevHold + prices[i];

        // newRest: "पिछले दिन भी विश्राम（prevRest）" या "पिछले दिन बेचा और कूलडाउन समाप्त हुआ（prevSold）" में से बड़ा मान
        int newRest = Math.max(prevRest,
            prevSold);

        // सभी गणना पूर्ण होने के बाद एक साथ अपडेट करना
        // गणना के दौरान पिछले दिन के मानों को अधिलेखित न करने के लिए, तीनों नए मान प्राप्त करके फिर असाइन करना
        prevHold = newHold;
        prevSold = newSold;
        prevRest = newRest;
    }
    // अंतिम दिन शेयर धारित रखकर समाप्त करना（prevHold）लाभ को निश्चित नहीं कर पाता इसलिए इष्टतम नहीं है
    // sold और rest में से बड़ा मान अधिकतम लाभ है
    return Math.max(prevSold, prevRest);
}
```
