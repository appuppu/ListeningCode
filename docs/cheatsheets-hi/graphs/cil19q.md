# सभी कोर्स पूरे किए जा सकते हैं या नहीं यह निर्धारित करना — Determining if All Courses Can Be Completed

## समस्या का सार

`0` से `n-1` तक लेबल किए गए `numCourses` कोर्स और पूर्व शर्तों की जोड़ियों की एक सूची `prerequisites` दी गई है। प्रत्येक जोड़ी `[a, b]` का अर्थ है "कोर्स `a` लेने से पहले कोर्स `b` पूरा करना आवश्यक है"। सभी कोर्स पूरे किए जा सकते हैं या नहीं, यह `boolean` के रूप में लौटाना है। यह एक निर्देशित ग्राफ में साइकल (चक्रीय निर्भरता) की उपस्थिति का पता लगाने की समस्या है।

## मूल विचार

कोर्स की निर्भरताओं को निर्देशित ग्राफ के रूप में देखें, तो सभी कोर्स पूरे किए जा सकते हैं या नहीं, यह "ग्राफ में साइकल है या नहीं" के समान है। इन-डिग्री (किसी नोड में आने वाली भुजाओं की संख्या) 0 वाले नोड्स से क्रमशः प्रोसेस करते हुए टोपोलॉजिकल सॉर्ट किया जाता है, और यदि सभी नोड्स प्रोसेस हो जाएं तो साइकल मौजूद नहीं है।

## विचार प्रक्रिया

1. **समस्या को ग्राफ में बदलें**: प्रत्येक कोर्स को नोड और प्रत्येक पूर्व शर्त `[a, b]` को "`b` → `a`" की निर्देशित भुजा के रूप में लेकर एडजेसेंसी लिस्ट बनाएं। इससे निर्भरता संबंध ग्राफ संरचना में व्यक्त होता है
2. **साइकल होने पर सभी कोर्स पूरे करना असंभव है**: यदि कोर्स A, B पर निर्भर है और B, A पर निर्भर है — ऐसी चक्रीय निर्भरता होने पर दोनों में से कोई भी पहले नहीं लिया जा सकता। इसलिए समस्या "निर्देशित ग्राफ में साइकल है या नहीं" के निर्धारण में बदल जाती है
3. **इन-डिग्री पर ध्यान दें**: प्रत्येक नोड की इन-डिग्री (पूर्व शर्तों की संख्या) गिनें। इन-डिग्री 0 वाले नोड्स की कोई पूर्व शर्त नहीं है, इसलिए उन्हें तुरंत लिया जा सकता है। इन्हें प्रारंभ बिंदु के रूप में उपयोग करें
4. **इन-डिग्री 0 वाले नोड्स को क्यू में डालकर प्रोसेसिंग शुरू करें**: BFS की तरह क्यू का उपयोग करें और इन-डिग्री 0 वाले नोड्स को क्रमशः प्रोसेस करें। प्रोसेस किए गए नोड से निकलने वाली भुजाओं के गंतव्य नोड्स की इन-डिग्री 1 घटाएं, और जिन नोड्स की इन-डिग्री 0 हो जाए उन्हें नए सिरे से क्यू में जोड़ें
5. **प्रोसेस किए गए नोड्स की संख्या से निर्धारण करें**: यदि सभी नोड्स प्रोसेस हो जाएं (प्रोसेस काउंट == `numCourses`) तो साइकल मौजूद नहीं है और सभी कोर्स पूरे किए जा सकते हैं। साइकल के अंदर के नोड्स की इन-डिग्री कभी 0 नहीं होती, इसलिए वे बिना प्रोसेस हुए रह जाते हैं

## पूर्व ज्ञान

### एडजेसेंसी लिस्ट (Adjacency List) क्या है

ग्राफ को व्यक्त करने की एक डेटा संरचना है। प्रत्येक नोड के लिए, उस नोड से भुजा जाने वाले गंतव्य नोड्स की सूची रखी जाती है। इसे `List<List<Integer>>` से कार्यान्वित किया जाता है, और `graph.get(i)` से नोड `i` के एडजेसेंट नोड्स की सूची प्राप्त की जा सकती है।

```java
List<List<Integer>> graph = new ArrayList<>();
for (int i = 0; i < n; i++)
    graph.add(new ArrayList<>());  // प्रत्येक नोड के लिए खाली सूची बनाएं
graph.get(0).add(1);               // नोड 0 से नोड 1 तक की भुजा जोड़ें
graph.get(0);                       // नोड 0 के एडजेसेंट नोड्स की सूची → [1]
```

### इन-डिग्री (In-degree) क्या है

निर्देशित ग्राफ में किसी नोड में आने वाली भुजाओं की संख्या है। इन-डिग्री 0 वाला नोड किसी भी नोड पर निर्भर नहीं है। `inDegree[i]` ऐरे से नोड `i` की इन-डिग्री प्रबंधित की जाती है।

```java
int[] inDegree = new int[n];   // सभी नोड्स की इन-डिग्री को 0 से आरंभ करें
inDegree[0]++;                  // नोड 0 की इन-डिग्री 1 बढ़ाएं
```

### Queue (क्यू) क्या है

फर्स्ट-इन फर्स्ट-आउट (FIFO) डेटा संरचना है। BFS में प्रोसेसिंग की प्रतीक्षा कर रहे नोड्स को प्रबंधित करने के लिए इसका उपयोग किया जाता है। `offer` से अंत में जोड़ा जाता है और `poll` से आरंभ से निकाला जाता है।

```java
Queue<Integer> queue = new LinkedList<>();
queue.offer(0);       // क्यू में 0 जोड़ें
queue.poll();          // क्यू के आरंभ से निकालकर लौटाएं → 0
queue.isEmpty();       // क्यू खाली है या नहीं boolean के रूप में लौटाएं → true
```

## गणना जटिलता

| | मान |
|---|---|
| Time | O(V + E) — सभी नोड्स (V) और सभी भुजाओं (E) को एक-एक बार प्रोसेस किया जाता है |
| Space | O(V + E) — एडजेसेंसी लिस्ट में सभी भुजाएं, इन-डिग्री ऐरे और क्यू में सभी नोड्स संग्रहीत किए जाते हैं |

## कोड

```java
// इनपुट: कोर्स की संख्या numCourses और पूर्व शर्तों की ऐरे prerequisites (प्रत्येक तत्व [a, b] है जो "b → a" की निर्भरता दर्शाता है)
// आउटपुट: सभी कोर्स पूरे किए जा सकते हैं तो true, साइकल होने पर पूरा करना असंभव है तो false
boolean canFinish(int numCourses, int[][] prerequisites) {
    // प्रत्येक नोड की इन-डिग्री (पूर्व शर्तों की संख्या) संग्रहीत करने वाला ऐरे। इन-डिग्री "उस कोर्स की कितनी पूर्व शर्तें हैं" यह दर्शाती है
    int[] inDegree = new int[numCourses];

    // एडजेसेंसी लिस्ट से ग्राफ बनाएं। graph.get(i) नोड i से भुजा जाने वाले गंतव्य नोड्स की सूची है
    List<List<Integer>> graph = new ArrayList<>();
    for (int i = 0; i < numCourses; i++)
        graph.add(new ArrayList<>());

    // प्रत्येक पूर्व शर्त से भुजा जोड़ें और इन-डिग्री अपडेट करें। इससे निर्भरता ग्राफ और प्रत्येक नोड की इन-डिग्री पूरी हो जाती है
    for (int[] p : prerequisites) {
        graph.get(p[1]).add(p[0]);  // p[1] → p[0] की भुजा जोड़ें
        inDegree[p[0]]++;           // p[0] की इन-डिग्री 1 बढ़ाएं
    }

    // इन-डिग्री 0 वाले नोड्स (बिना पूर्व शर्त) को क्यू में जोड़ें। ये वे कोर्स हैं जो सबसे पहले लिए जा सकते हैं
    Queue<Integer> queue = new LinkedList<>();
    for (int i = 0; i < numCourses; i++)
        if (inDegree[i] == 0)
            queue.offer(i);

    // BFS से इन-डिग्री 0 वाले नोड्स से क्रमशः प्रोसेस करें
    int count = 0;  // प्रोसेस किए गए कोर्स की संख्या ट्रैक करने वाला वेरिएबल
    while (!queue.isEmpty()) {
        int course = queue.poll();
        count++;  // इस नोड को पूर्ण माना जाए

        // एडजेसेंट नोड्स की इन-डिग्री 1 घटाएं (एक पूर्व शर्त पूरी हुई)। 0 हो जाने पर सभी पूर्व शर्तें पूरी हो गई हैं इसलिए क्यू में जोड़ें
        for (int nei : graph.get(course))
            if (--inDegree[nei] == 0)
                queue.offer(nei);
    }

    // सभी नोड्स प्रोसेस हो गए तो साइकल नहीं है (सभी कोर्स पूरे किए जा सकते हैं)। साइकल के अंदर के नोड्स की इन-डिग्री 0 नहीं होती इसलिए वे बिना प्रोसेस हुए रह जाते हैं
    return count == numCourses;
}
```
