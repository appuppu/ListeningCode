# Designing a Least Recently Used Cache — क्षमता से अधिक होने पर सबसे पुराने उपयोग किए गए तत्व को स्वचालित रूप से हटाने वाला कैश डिज़ाइन करना

## समस्या का सार

पूर्णांक कुंजी और मान को संग्रहीत करने वाला कैश डिज़ाइन करना है। `get(key)` और `put(key, value)` — इन दो संक्रियाओं का समर्थन करना है, और दोनों को O(1) में कार्य करना आवश्यक है। जब कैश की क्षमता `capacity` से अधिक हो जाए, तो **सबसे लंबे समय से उपयोग न किया गया (Least Recently Used) तत्व** स्वचालित रूप से हटाकर नया तत्व सम्मिलित करना है।

## मूल विचार

Java के LinkedHashMap को एक्सेस क्रम मोड में बनाकर `removeEldestEntry` को ओवरराइड करने पर, प्रत्येक get/put के समय एक्सेस क्रम स्वचालित रूप से अपडेट होता है, और क्षमता से अधिक होने पर सबसे पुराना तत्व स्वचालित रूप से हटा दिया जाता है। LRU कैश की संपूर्ण कार्यक्षमता केवल LinkedHashMap की आंतरिक संरचना से ही प्राप्त की जा सकती है।

## विचार प्रक्रिया

1. **O(1) का get/put आवश्यक है**: कुंजी से मान तक तेज़ पहुँच के लिए HashMap आवश्यक है। लेकिन सामान्य HashMap में तत्वों के उपयोग क्रम को ट्रैक करने की सुविधा नहीं होती
2. **उपयोग क्रम की ट्रैकिंग आवश्यक है**: LRU में "सबसे पुराने उपयोग किए गए तत्व" की पहचान करना आवश्यक है। जब भी किसी तत्व को एक्सेस किया जाता है, उसे "नवीनतम" स्थान पर ले जाना होता है, और शीर्ष पर शेष तत्व "सबसे पुराना" बनता है — ऐसी क्रमबद्ध संरचना की आवश्यकता है
3. **LinkedHashMap इन दोनों को एक साथ प्रदान करता है**: Java का LinkedHashMap, HashMap की कार्यक्षमता के अतिरिक्त, आंतरिक रूप से द्विदिशात्मक लिंक्ड लिस्ट रखता है। कन्स्ट्रक्टर के तीसरे पैरामीटर में `true` पास करने पर एक्सेस क्रम मोड सक्रिय हो जाता है, और प्रत्येक get या put पर संबंधित तत्व स्वचालित रूप से लिस्ट के अंत में चला जाता है
4. **क्षमता से अधिक होने पर स्वचालित हटाना**: LinkedHashMap के `removeEldestEntry` मेथड को ओवरराइड करके, `size() > capacity` होने पर `true` लौटाना है। LinkedHashMap नया तत्व put करने के तुरंत बाद इस मेथड को कॉल करता है, और `true` लौटने पर लिस्ट के शीर्ष (सबसे पुराने तत्व) को स्वचालित रूप से हटा देता है
5. **get में अनुपस्थित कुंजी का मामला**: समस्या के विनिर्देश के अनुसार कुंजी अनुपस्थित होने पर `-1` लौटाना आवश्यक है। `getOrDefault(key, -1)` का उपयोग करने पर, अस्तित्व जाँच और मान प्राप्ति एक ही कॉल में हो जाती है
6. **अंतिम संरचना**: कन्स्ट्रक्टर में LinkedHashMap को एक्सेस क्रम मोड में बनाकर `removeEldestEntry` को ओवरराइड करना है — बस इतना करने पर, get/put दोनों मेथड LinkedHashMap को सीधे सौंपने मात्र से काम कर जाते हैं

## पूर्वापेक्षित ज्ञान

### LinkedHashMap क्या है

HashMap की संपूर्ण कार्यक्षमता के अतिरिक्त, तत्वों के क्रम को आंतरिक द्विदिशात्मक लिंक्ड लिस्ट में बनाए रखने वाली डेटा संरचना है। कन्स्ट्रक्टर के तीसरे पैरामीटर `accessOrder` में `true` पास करने पर, जब भी किसी तत्व को एक्सेस (get या put) किया जाता है, वह तत्व लिस्ट के अंत में चला जाता है। लिस्ट के शीर्ष पर सबसे लंबे समय से एक्सेस न किया गया तत्व बना रहता है।

```java
// पहला पैरामीटर: प्रारंभिक क्षमता, दूसरा पैरामीटर: लोड फैक्टर, तीसरा पैरामीटर: true=एक्सेस क्रम मोड
LinkedHashMap<Integer, Integer> map = new LinkedHashMap<>(16, 0.75f, true);
map.put(1, 10);     // कुंजी 1 में मान 10 संग्रहीत करता है। लिस्ट: [1]
map.put(2, 20);     // कुंजी 2 में मान 20 संग्रहीत करता है। लिस्ट: [1, 2]
map.get(1);          // कुंजी 1 को एक्सेस करता है। लिस्ट: [2, 1]（1 अंत में चला जाता है）
map.put(3, 30);     // कुंजी 3 में मान 30 संग्रहीत करता है। लिस्ट: [2, 1, 3]
// इस समय लिस्ट के शीर्ष पर कुंजी 2 "सबसे पुराना उपयोग किया गया तत्व" है
```

### removeEldestEntry क्या है

LinkedHashMap द्वारा नया तत्व put करने के तुरंत बाद स्वचालित रूप से कॉल किया जाने वाला मेथड है। जब यह मेथड `true` लौटाता है, तो LinkedHashMap लिस्ट के शीर्ष पर स्थित सबसे पुराने तत्व को स्वचालित रूप से हटा देता है। डिफ़ॉल्ट रूप से यह सदैव `false` लौटाता है, इसलिए हटाने की शर्त परिभाषित करने के लिए इसे ओवरराइड करना होता है।

```java
LinkedHashMap<Integer, Integer> map = new LinkedHashMap<>(cap, 0.75f, true) {
    @Override
    protected boolean removeEldestEntry(Map.Entry<Integer, Integer> eldest) {
        return size() > cap;  // आकार क्षमता से अधिक होने पर true लौटाता है और सबसे पुराने तत्व को हटवाता है
    }
};
```

### getOrDefault क्या है

Map इंटरफ़ेस का मेथड है। यदि कुंजी मौजूद है तो उसका मान लौटाता है, और मौजूद नहीं है तो दूसरे पैरामीटर में निर्दिष्ट डिफ़ॉल्ट मान लौटाता है। `containsKey` और `get` की दो अलग-अलग कॉल को एक ही कॉल में संयोजित करता है।

```java
map.put(1, 10);
map.getOrDefault(1, -1);   // कुंजी 1 मौजूद है इसलिए मान 10 लौटाता है
map.getOrDefault(99, -1);  // कुंजी 99 मौजूद नहीं है इसलिए डिफ़ॉल्ट मान -1 लौटाता है
```

## गणना जटिलता

| | मान |
|---|---|
| Time | O(1) — get/put दोनों में HashMap की पहुँच और लिस्ट के भीतर स्थानांतरण सभी O(1) में कार्य करते हैं |
| Space | O(n) — कैश की क्षमता के बराबर तत्वों को LinkedHashMap में संग्रहीत करता है（n = capacity） |

## कोड

```java
// इनपुट: कन्स्ट्रक्टर में पूर्णांक capacity（कैश की अधिकतम क्षमता）, get में पूर्णांक key, put में पूर्णांक key और पूर्णांक value
// आउटपुट: get कुंजी के संगत मान लौटाता है（कुंजी अनुपस्थित होने पर -1）। put कोई मान नहीं लौटाता
class LRUCache {
    LinkedHashMap<Integer, Integer> map;
    // क्षमता संग्रहीत करने वाला इन्स्टेन्स चर। removeEldestEntry में हटाने के निर्णय हेतु उपयोग होता है
    int cap;

    // क्षमता प्राप्त करके एक्सेस क्रम मोड का LinkedHashMap प्रारंभ करता है
    LRUCache(int capacity) {
        cap = capacity;
        // पहला पैरामीटर: प्रारंभिक क्षमता, दूसरा पैरामीटर: डिफ़ॉल्ट लोड फैक्टर, तीसरा पैरामीटर: true=एक्सेस क्रम मोड
        // एक्सेस क्रम मोड के कारण, प्रत्येक get या put पर संबंधित तत्व स्वचालित रूप से लिस्ट के अंत में चला जाता है
        map = new LinkedHashMap<>(cap, 0.75f, true) {
            // प्रत्येक put पर LinkedHashMap द्वारा स्वचालित रूप से कॉल किया जाने वाला मेथड
            // size() > cap होने पर true लौटाता है और लिस्ट के शीर्ष पर स्थित सबसे पुराने तत्व को स्वचालित रूप से हटवाता है
            // इससे कैश का आकार सदैव cap के बराबर या उससे कम बना रहता है
            protected boolean removeEldestEntry(Map.Entry<Integer, Integer> e) {
                return size() > cap;
            }
        };
    }

    // कुंजी मौजूद होने पर: एक्सेस क्रम मोड के कारण संबंधित तत्व लिस्ट के अंत में चला जाता है（नवीनतम के रूप में दर्ज होता है）, और मान लौटाया जाता है
    // कुंजी अनुपस्थित होने पर: डिफ़ॉल्ट मान -1 लौटाया जाता है
    int get(int key) {
        return map.getOrDefault(key, -1);
    }

    // कुंजी और मान का युग्म सम्मिलित या अपडेट करता है
    // सम्मिलन के बाद removeEldestEntry स्वचालित रूप से कॉल होता है, और size() > cap होने पर सबसे पुराना तत्व हटा दिया जाता है
    // कुंजी पहले से मौजूद होने पर मान अधिलेखित हो जाता है, और संबंधित तत्व लिस्ट के अंत में चला जाता है
    void put(int key, int value) {
        map.put(key, value);
    }
}
```
