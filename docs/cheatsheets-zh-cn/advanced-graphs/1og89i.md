# Reconstructing a Flight Itinerary — 从航空机票中重构字典序最小的行程

## 问题的本质

给定一个由出发机场和到达机场的配对表示的航空机票列表。从JFK出发，恰好使用每张机票一次，重构完整的行程。如果存在多个有效行程，则返回字典序最小的行程。

## 核心思路

这是一个恰好经过所有边（机票）一次的欧拉路径问题。用PriorityQueue管理每个机场的目的地，就能自动保证字典序最小；用Hierholzer算法从后往前构建行程，就能正确处理死胡同。

## 思考过程

1. **恰好使用每张机票一次 = 欧拉路径**：每张机票是有向图中的一条边，求恰好经过所有边一次的路径，该问题可归结为欧拉路径（Eulerian Path）问题
2. **保证字典序最小需要排序**：当某个机场有多个目的地时，需要优先选择字典序较小的目的地。将每个机场的目的地存入PriorityQueue（最小堆），只需调用`poll()`即可始终获得字典序最小的目的地
3. **单纯的贪心法无法处理死胡同**：如果始终选择字典序最小的目的地，可能会在还有未使用的边时先到达死胡同。例如，当存在JFK→A→JFK→B的机票时，从JFK先选A可以沿A→JFK→B前进，但先选B则会在B处陷入死胡同
4. **用Hierholzer算法从后往前构建**：在DFS中，当某节点没有目的地（到达死胡同）时，将该节点添加到结果列表的**头部**。这样死胡同会被放置在行程的末尾，其余的边在递归回溯时会以正确的顺序依次添加到头部
5. **递归DFS的运行方式**：从当前节点通过PriorityQueue取出字典序最小的目的地，递归地进行DFS。当没有目的地时，将当前节点添加到结果列表的头部。使用LinkedList的`addFirst`可以以O(1)的时间复杂度完成头部插入
6. **最终返回的结果**：所有DFS完成后，直接返回结果列表（LinkedList）。列表中存储的是从JFK开始的字典序最小的行程

## 前置知识

### PriorityQueue（优先队列）

添加元素时会自动排序，取出时始终返回最小元素的数据结构。内部通过堆实现，添加和取出的时间复杂度均为O(log n)。

```java
PriorityQueue<String> pq = new PriorityQueue<>();  // 按字符串自然顺序（字典序）创建最小堆
pq.offer("SFO");       // 添加"SFO"
pq.offer("ATL");       // 添加"ATL"
pq.poll();             // 取出并删除最小元素"ATL" → "ATL"
pq.isEmpty();          // 返回队列是否为空的boolean值 → false（"SFO"仍在队列中）
```

### computeIfAbsent

仅当HashMap中不存在指定键时，才通过指定的函数生成值并注册，然后返回该值的方法。如果键已存在，则直接返回现有的值。将`get`、`null`检查和`put`三个步骤合并为一行代码。

```java
Map<String, PriorityQueue<String>> graph = new HashMap<>();
// 如果"JFK"键不存在，则创建新的PriorityQueue并注册，然后返回该PriorityQueue
graph.computeIfAbsent("JFK", k -> new PriorityQueue<>()).offer("SFO");
// "JFK"键已存在，因此返回现有的PriorityQueue（不会创建新的）
graph.computeIfAbsent("JFK", k -> new PriorityQueue<>()).offer("ATL");
```

### LinkedList 的 addFirst

以O(1)的时间复杂度将元素添加到列表头部的方法。与普通的`add`（尾部添加）不同，它无需将现有元素向后移动即可在头部插入。在Hierholzer算法中用于逆序构建结果。

```java
LinkedList<String> result = new LinkedList<>();
result.addFirst("JFK");   // result: ["JFK"]
result.addFirst("ATL");   // result: ["ATL", "JFK"]
result.addFirst("SFO");   // result: ["SFO", "ATL", "JFK"]
```

### Hierholzer算法

用于求解欧拉路径（恰好经过所有边一次的路径）的算法。在DFS过程中消耗边并前进，当到达死胡同时将该节点添加到结果的头部。使用完所有边后，结果列表中会以正确的顺序存储欧拉路径。该算法能够自然地将死胡同放置在行程末尾，因此非常适合解决本问题。

## 计算复杂度

| | 值 |
|---|---|
| Time | O(E log E) — 将每张机票（边）添加到PriorityQueue和从中取出时，每次操作的开销为log E |
| Space | O(V + E) — 图的邻接表中存储所有边，递归栈的最大深度等于边的数量 |

## 代码

```java
// 输入：航空机票列表 tickets（每张机票是 [出发机场, 到达机场] 的字符串对）
// 输出：以 List<String> 的形式返回从JFK开始的字典序最小的行程
public List<String> findItinerary(List<List<String>> tickets) {
    // 键=出发机场，值=按字典序管理到达机场的PriorityQueue
    // 使用PriorityQueue，取出时始终能获得字典序最小的目的地
    Map<String, PriorityQueue<String>> graph = new HashMap<>();

    // 根据所有机票构建图
    // 通过computeIfAbsent，如果src键首次出现则创建新的PriorityQueue，已存在则直接获取
    for (List<String> t : tickets) {
        graph.computeIfAbsent(t.get(0), k -> new PriorityQueue<>())
             .offer(t.get(1));
    }

    // 用于存储结果的LinkedList（使用addFirst进行O(1)的头部插入）
    LinkedList<String> result = new LinkedList<>();

    // 从JFK开始DFS
    dfs("JFK", graph, result);
    return result;
}

void dfs(String curr,
          Map<String, PriorityQueue<String>> graph,
          LinkedList<String> result) {
    // 获取当前机场可到达的目的地的PriorityQueue
    PriorityQueue<String> dests = graph.get(curr);

    // 当存在目的地时，取出字典序最小的目的地并进行DFS
    // 注意：poll()会删除元素，因此同一条边（机票）不会被使用两次
    while (dests != null && !dests.isEmpty()) {
        dfs(dests.poll(), graph, result);
    }

    // 到达死胡同后，将当前机场添加到结果列表的头部
    // 通过头部插入，死胡同节点会被放置在行程的末尾侧，
    // 后续添加的节点会被正确地放置在行程的前方
    result.addFirst(curr);
}
```
