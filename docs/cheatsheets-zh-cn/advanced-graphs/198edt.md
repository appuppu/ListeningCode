# Finding the Minimum Time to Swim Across a Grid — 求解游过网格的最短时间

## 问题的本质

给定一个 n×n 的网格，每个单元格包含一个从 0 到 n²-1 的唯一海拔值。只有当当前时刻**大于等于两个单元格的海拔值**时，才能从一个单元格游到相邻单元格（上下左右）。求从左上角 (0,0) 到达右下角 (n-1,n-1) 所需的**最小时刻**。起始时刻为 grid[0][0] 的值。

## 核心思路

路径上经过的单元格海拔的**最大值**即为该路径所需的时刻。使用最小堆按照「当前可达单元格中所需时刻最小的单元格」的顺序进行探索，第一次到达终点时的时刻即为最优解。

## 思考过程

1. **转换移动条件**：从单元格 A 移动到单元格 B 需要满足「时刻 ≥ max(A, B)」。也就是说，从起点到终点的整条路径所需的时刻等于「路径上所有单元格海拔的最大值」。因此问题归结为「找到一条路径，使得路径上的最大海拔最小」
2. **发现与最短路径问题的相似性**：普通的 Dijkstra 算法最小化「路径上边权的总和」，而本问题最小化「路径上单元格海拔的最大值」。只需将求和替换为取最大值，即可直接套用 Dijkstra 的框架
3. **使用优先队列从最小时刻的单元格开始扩展**：将单元格按照「到达该单元格所需的时刻」存入最小堆（PriorityQueue）。始终从所需时刻最小的单元格开始扩展，可以保证每个单元格第一次被取出时的时刻就是最优值
4. **计算到达相邻单元格的所需时刻**：当前单元格 (r,c) 的所需时刻为 `time` 时，到达相邻单元格 (nr,nc) 的所需时刻为 `Math.max(time, grid[nr][nc])`。这是因为「到当前位置为止路径上的最大海拔」与「下一个单元格的海拔」中较大的那个值，就是新路径的所需时刻
5. **通过访问标记防止重复处理**：从最小堆中取出的单元格，其最优时刻在该时刻点已经确定。使用访问数组 `vis` 进行标记，避免对同一单元格重复处理。这与 Dijkstra 算法中已确定节点的思路相同
6. **到达终点时立即返回**：当从堆中取出的单元格为 (n-1, n-1) 时，此时的 `time` 即为最小时刻。由于最小堆按照时刻从小到大的顺序进行处理，第一次到达终点时即为最优解

## 前置知识

### 什么是 PriorityQueue（最小堆）

PriorityQueue 是一种可以按照优先级顺序取出元素的数据结构。默认情况下，最小值具有最高优先级并被优先取出。插入和取出操作的时间复杂度均为 O(log n)。在 Dijkstra 算法中，PriorityQueue 用于高效地执行「从未确定的节点中选择代价最小的节点」这一操作。

```java
// 创建一个按 int[] 第 0 个元素升序排列的最小堆
PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[0] - b[0]);
pq.offer(new int[]{5, 0, 0});   // 添加元素（O(log n)）
pq.offer(new int[]{3, 1, 0});   // 添加元素
int[] min = pq.poll();          // 取出并删除最小元素 → {3, 1, 0}
boolean empty = pq.isEmpty();   // 判断队列是否为空 → false
```

### 什么是 Dijkstra 算法的变体

普通的 Dijkstra 算法最小化边权的**总和**，而本问题最小化路径上海拔的**最大值**。只需将距离更新公式从 `dist[next] = dist[cur] + weight` 改为 `dist[next] = max(dist[cur], grid[next])`，Dijkstra 算法的正确性（从最小堆中取出时最优值已确定的性质）仍然成立。

### 四方向相邻单元格探索

网格上单元格 (r,c) 的上下左右相邻单元格，可以通过加上方向向量 `{{0,1},{0,-1},{1,0},{-1,0}}` 来枚举。需要进行越界检查（0 ≤ nr < n 且 0 ≤ nc < n），只处理有效的单元格。

```java
int[][] dir = {{0,1},{0,-1},{1,0},{-1,0}};  // 右、左、下、上四个方向
for (int[] d : dir) {
    int nr = r + d[0];  // 相邻单元格的行
    int nc = c + d[1];  // 相邻单元格的列
    if (nr >= 0 && nr < n && nc >= 0 && nc < n) {
        // (nr, nc) 是有效的相邻单元格
    }
}
```

## 复杂度

| | 值 |
|---|---|
| Time | O(n² log n) — 对 n² 个单元格各最多进行一次堆的入队和出队操作。每次堆操作的时间复杂度为 O(log n²) = O(log n) |
| Space | O(n²) — 访问数组和堆各最多保存 n² 个单元格 |

## 代码

```java
// 输入：n×n 的整数数组 grid（每个单元格包含一个从 0 到 n²-1 的唯一海拔值）
// 输出：返回从左上角 (0,0) 到达右下角 (n-1,n-1) 所需的最小时刻（int 类型）
int swimInWater(int[][] grid) {
    int n = grid.length;
    // 管理每个单元格最优时刻是否已确定的访问数组（vis[r][c] = true 表示已确定）
    boolean[][] vis = new boolean[n][n];
    // 按所需时刻从小到大取出的最小堆（元素：{时刻, 行, 列}）
    // 比较函数 (a,b)->a[0]-b[0] 使元素按第 0 个元素（所需时刻）升序取出
    PriorityQueue<int[]> pq =
        new PriorityQueue<>(
            (a, b) -> a[0] - b[0]);
    // 将起点添加到堆中，并标记为已访问
    // 第 0 个元素为所需时刻，第 1 个元素为行，第 2 个元素为列
    pq.offer(new int[]
        {grid[0][0], 0, 0});
    vis[0][0] = true;
    // 上下左右四个方向向量
    int[][] dir =
        {{0,1},{0,-1},{1,0},{-1,0}};
    while (!pq.isEmpty()) {
        // 取出所需时刻最小的单元格（由最小堆的性质保证，此时最优时刻已确定）
        int[] cur = pq.poll();
        int time = cur[0];
        int r = cur[1], c = cur[2];
        // 到达终点时，该时刻即为最优解（因为按照最小时刻顺序处理，第一次到达即为最优）
        if (r == n-1 && c == n-1)
            return time;
        // 探索四个方向的相邻单元格
        for (int[] d : dir) {
            int nr = r+d[0];
            int nc = c+d[1];
            // 只处理在范围内且未访问的单元格
            if (nr >= 0 && nr < n
                && nc >= 0 && nc < n
                && !vis[nr][nc]) {
                // 注意：在添加到堆时就标记为已访问，防止同一单元格被多次添加到堆中
                vis[nr][nc] = true;
                // 路径上的最大海拔即为所需时刻（取「到当前位置为止的最大海拔」与「下一个单元格的海拔」中的较大值）
                int nt = Math.max(
                    time,grid[nr][nc]);
                pq.offer(new int[]
                    {nt, nr, nc});
            }
        }
    }
    // 根据问题约束，网格是连通的，因此不会执行到此处
    return -1;
}
```
