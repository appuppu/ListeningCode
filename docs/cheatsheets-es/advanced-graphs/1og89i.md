# Reconstructing a Flight Itinerary — Reconstruir el itinerario de viaje en orden lexicográfico mínimo a partir de boletos aéreos

## Esencia del problema

Se proporciona una lista de boletos aéreos representados como pares de aeropuerto de salida y aeropuerto de llegada. Se debe reconstruir el itinerario partiendo de JFK, utilizando cada boleto exactamente una vez. Si existen múltiples itinerarios válidos, se debe devolver el que sea lexicográficamente menor.

## Idea central

Este es un problema de camino euleriano, donde se debe recorrer cada arista (boleto) exactamente una vez. Si se gestionan los destinos de cada aeropuerto con un PriorityQueue, el orden lexicográfico mínimo se garantiza automáticamente. Además, al construir el itinerario desde el final con el algoritmo de Hierholzer, los callejones sin salida se manejan correctamente.

## Proceso de razonamiento

1. **Usar todos los boletos exactamente una vez = camino euleriano**: Cada boleto es una arista de un grafo dirigido, y el problema de encontrar un camino que recorra todas las aristas exactamente una vez se reduce a un problema de camino euleriano (Eulerian Path)
2. **Se necesita ordenamiento para garantizar el orden lexicográfico mínimo**: Cuando un aeropuerto tiene múltiples destinos, se desea elegir primero el que sea lexicográficamente menor. Si se almacenan los destinos de cada aeropuerto en un PriorityQueue (min-heap), basta con llamar a `poll()` para obtener siempre el destino lexicográficamente menor
3. **Un enfoque voraz simple no puede manejar los callejones sin salida**: Si siempre se elige el destino lexicográficamente menor, puede ocurrir que se llegue a un callejón sin salida mientras aún quedan aristas sin usar. Por ejemplo, si existen los boletos JFK→A→JFK→B, al elegir A primero desde JFK se puede avanzar A→JFK→B, pero si se elige B primero, se llega a un callejón sin salida en B
4. **Se construye el itinerario desde el final con el algoritmo de Hierholzer**: En el DFS, cuando un nodo ya no tiene destinos (se llega a un callejón sin salida), se agrega al **inicio** de la lista de resultados. De esta forma, los callejones sin salida se colocan al final del itinerario, y las aristas restantes se agregan al inicio en el orden correcto durante el retroceso de la recursión
5. **Funcionamiento del DFS recursivo**: Desde el nodo actual, se extrae el destino lexicográficamente menor del PriorityQueue y se realiza el DFS recursivamente. Cuando ya no quedan destinos, se agrega el nodo actual al inicio de la lista de resultados. Usando `addFirst` de LinkedList, la inserción al inicio se realiza en O(1)
6. **Resultado final**: Después de completar todo el DFS, se devuelve la lista de resultados (LinkedList) tal cual. La lista contiene el itinerario lexicográficamente menor que comienza desde JFK

## Conocimientos previos

### ¿Qué es un PriorityQueue (cola de prioridad)?

Es una estructura de datos que ordena automáticamente los elementos al agregarlos y siempre devuelve el elemento mínimo al extraerlo. Internamente está implementada como un heap, y tanto la inserción como la extracción operan en O(log n).

```java
PriorityQueue<String> pq = new PriorityQueue<>();  // Se crea un min-heap con el orden natural de las cadenas (orden lexicográfico)
pq.offer("SFO");       // Se agrega "SFO"
pq.offer("ATL");       // Se agrega "ATL"
pq.poll();             // Se extrae y elimina el elemento mínimo "ATL" → "ATL"
pq.isEmpty();          // Devuelve un booleano indicando si la cola está vacía → false (queda "SFO")
```

### ¿Qué es computeIfAbsent?

Es un método de HashMap que, solo si la clave no existe, genera un valor con la función especificada, lo registra y lo devuelve. Si la clave ya existe, devuelve el valor existente tal cual. Permite escribir en una sola línea los tres pasos de hacer `get`, verificar si es `null` y hacer `put`.

```java
Map<String, PriorityQueue<String>> graph = new HashMap<>();
// Si la clave "JFK" no existe, se crea un nuevo PriorityQueue, se registra y se devuelve ese PriorityQueue
graph.computeIfAbsent("JFK", k -> new PriorityQueue<>()).offer("SFO");
// Como la clave "JFK" ya existe, se devuelve el PriorityQueue existente (no se crea uno nuevo)
graph.computeIfAbsent("JFK", k -> new PriorityQueue<>()).offer("ATL");
```

### ¿Qué es addFirst de LinkedList?

Es un método que agrega un elemento al inicio de la lista en O(1). A diferencia de `add` (que agrega al final), permite insertar al inicio sin desplazar los elementos existentes hacia atrás. Se utiliza en el algoritmo de Hierholzer para construir el resultado en orden inverso.

```java
LinkedList<String> result = new LinkedList<>();
result.addFirst("JFK");   // result: ["JFK"]
result.addFirst("ATL");   // result: ["ATL", "JFK"]
result.addFirst("SFO");   // result: ["SFO", "ATL", "JFK"]
```

### ¿Qué es el algoritmo de Hierholzer?

Es un algoritmo para encontrar un camino euleriano (un camino que recorre todas las aristas exactamente una vez). Avanza consumiendo aristas mediante DFS y, al llegar a un callejón sin salida, agrega el nodo al inicio del resultado. Después de usar todas las aristas, la lista de resultados contiene el camino euleriano en el orden correcto. Es adecuado para este problema porque permite colocar naturalmente los callejones sin salida al final del itinerario.

## Complejidad computacional

| | Valor |
|---|---|
| Time | O(E log E) — Cada boleto (arista) tiene un costo de log E al agregarlo y extraerlo del PriorityQueue |
| Space | O(V + E) — Se almacenan todas las aristas en la lista de adyacencia del grafo, y la pila de recursión puede alcanzar una profundidad máxima igual al número de aristas |

## Código

```java
// Entrada: lista de boletos aéreos tickets (cada boleto es un par de cadenas [aeropuerto de salida, aeropuerto de llegada])
// Salida: devuelve el itinerario lexicográficamente menor que comienza desde JFK como List<String>
public List<String> findItinerary(List<List<String>> tickets) {
    // Clave=aeropuerto de salida, Valor=PriorityQueue que gestiona los aeropuertos de llegada en orden lexicográfico
    // Al usar PriorityQueue, siempre se obtiene el destino lexicográficamente menor al extraer
    Map<String, PriorityQueue<String>> graph = new HashMap<>();

    // Se construye el grafo a partir de todos los boletos
    // Mediante computeIfAbsent, si la clave src aparece por primera vez se crea un nuevo PriorityQueue; si ya existe, se obtiene el existente
    for (List<String> t : tickets) {
        graph.computeIfAbsent(t.get(0), k -> new PriorityQueue<>())
             .offer(t.get(1));
    }

    // LinkedList para almacenar los resultados (se usa addFirst para insertar al inicio en O(1))
    LinkedList<String> result = new LinkedList<>();

    // Se inicia el DFS desde JFK
    dfs("JFK", graph, result);
    return result;
}

void dfs(String curr,
          Map<String, PriorityQueue<String>> graph,
          LinkedList<String> result) {
    // Se obtiene el PriorityQueue de destinos accesibles desde el aeropuerto actual
    PriorityQueue<String> dests = graph.get(curr);

    // Mientras existan destinos, se extrae el lexicográficamente menor y se realiza el DFS
    // Nota: poll() elimina el elemento, por lo que nunca se recorre la misma arista (boleto) dos veces
    while (dests != null && !dests.isEmpty()) {
        dfs(dests.poll(), graph, result);
    }

    // Al llegar a un callejón sin salida, se agrega el aeropuerto actual al inicio de la lista de resultados
    // Al agregar al inicio, los nodos de callejón sin salida se colocan al final del itinerario,
    // y los nodos agregados posteriormente se colocan correctamente en la parte anterior del itinerario
    result.addFirst(curr);
}
```
