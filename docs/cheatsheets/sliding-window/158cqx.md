# Checking if a String Contains a Permutation of Another — 文字列が別の文字列の順列を含むか判定する

## 問題の本質

2つの文字列 `s1` と `s2` が与えられる。`s2` の中に `s1` のアナグラム（文字の並び替え）が**連続する部分文字列**として存在するかを判定し、存在すれば `true`、存在しなければ `false` を返す。

## 核心のアイデア

`s1` の順列が `s2` に含まれるとは、`s2` 内に `s1` と同じ長さで同じ文字頻度を持つ部分文字列が存在することである。固定長のスライディングウィンドウで `s2` を走査し、26文字の頻度が一致する数を差分更新することで、各スライドをO(1)で判定できる。

## 思考プロセス

1. **順列の条件を言い換える**: `s1` の順列が `s2` の部分文字列として存在するとは、`s2` 内に長さ `m`（= `s1` の長さ）の部分文字列で、各文字の出現回数が `s1` と完全に一致するものが存在することである
2. **固定長のウィンドウで走査する**: 部分文字列の長さは常に `m` なので、`s2` 上に長さ `m` の固定サイズウィンドウを置き、1文字ずつスライドさせながら文字頻度を比較すればよい
3. **頻度配列で文字の出現回数を管理する**: 英小文字は26種類なので、サイズ26の整数配列2つ（`s1F` と `winF`）で `s1` とウィンドウ内の文字頻度をそれぞれ管理する。配列の各インデックスが各文字に対応する
4. **毎回26要素を比較するのは無駄**: ウィンドウをスライドすると変化する文字は「新たに入る1文字」と「出ていく1文字」の最大2つだけである。26要素を毎回比較する代わりに、「26文字のうち頻度が一致している文字数」を `matches` カウンタで追跡し、差分だけを更新する
5. **matchesカウンタの更新ルール**: ある文字の頻度を変更するとき、変更前に一致していれば `matches` を1減らし、変更後に一致すれば `matches` を1増やす。この「変更前の判定→値の変更→変更後の判定」の順序を守ることで、カウンタの整合性を保つ
6. **判定条件**: `matches` が26になった時点で、全26文字の頻度が一致しているので `true` を返す。`s2` の末尾までスライドしても26にならなければ `false` を返す

## 前提知識

### スライディングウィンドウとは

配列や文字列上の連続する部分区間を、左端と右端を動かしながら走査する手法。固定長ウィンドウの場合、右端を1つ進めると同時に左端も1つ進めることで、ウィンドウサイズを一定に保つ。

```java
// 長さmの固定ウィンドウをs2上でスライドさせる基本形
for (int i = m; i < n; i++) {
    char entering = s2.charAt(i);       // ウィンドウに新たに入る文字（右端）
    char leaving = s2.charAt(i - m);    // ウィンドウから出ていく文字（左端）
}
```

### 頻度配列とは

各文字の出現回数を格納するサイズ26の整数配列。`'a'` をインデックス0、`'z'` をインデックス25に対応させる。`charAt(i) - 'a'` で文字をインデックスに変換する。

```java
int[] freq = new int[26];              // 全要素0で初期化される
freq[s.charAt(i) - 'a']++;            // 文字の出現回数を1増やす
freq[s.charAt(i) - 'a']--;            // 文字の出現回数を1減らす
```

### matchesカウンタとは

2つの頻度配列間で、同じインデックスの値が一致している個数を追跡するカウンタ。全26個が一致すれば `matches == 26` となり、2つの文字列の文字構成が同一であることを意味する。

```java
int matches = 0;
for (int i = 0; i < 26; i++) {
    if (s1F[i] == winF[i]) matches++;  // 一致している文字数を数える
}
// matches == 26 なら全文字の頻度が一致
```

## 計算量

| | 値 |
|---|---|
| Time | O(n) — `s2` を1回走査するだけで済む（各スライドはO(1)） |
| Space | O(1) — 頻度配列のサイズは常に26で、入力サイズに依存しない |

## コード

```java
// 入力: 文字列 s1（検索対象の順列）と文字列 s2（検索先の文字列）
// 出力: s2 が s1 の順列を部分文字列として含むなら true、含まないなら false
boolean checkInclusion(String s1, String s2) {
    int m = s1.length();
    int n = s2.length();

    // s1がs2より長い場合、順列が含まれることはないので即座にfalseを返す
    if (m > n) return false;

    // s1の文字頻度とウィンドウの文字頻度を格納するサイズ26の配列
    int[] s1F = new int[26];
    int[] winF = new int[26];

    // 最初のウィンドウ（先頭m文字）の頻度を計算する。s1とs2の先頭m文字を同時にカウント
    for (int i = 0; i < m; i++) {
        s1F[s1.charAt(i) - 'a']++;
        winF[s2.charAt(i) - 'a']++;
    }

    // 26文字のうち頻度が一致している文字数を数える（初期matchesの計算）
    int matches = 0;
    for (int i = 0; i < 26; i++) {
        if (s1F[i] == winF[i]) matches++;
    }

    // 最初のウィンドウで全26文字の頻度が一致していればtrueを返す
    if (matches == 26) return true;

    // ウィンドウを1文字ずつ右にスライドさせる（iはウィンドウ右端の次の位置）
    for (int i = m; i < n; i++) {
        // --- 新たにウィンドウに入る文字（右端）の処理 ---
        int idx = s2.charAt(i) - 'a';
        // 注意: 「変更前の判定→値の変更→変更後の判定」の順序を必ず守る
        if (winF[idx] == s1F[idx]) matches--;   // 変更前に一致していたらmatchesを減らす
        winF[idx]++;                              // ウィンドウに入るので頻度を1増やす
        if (winF[idx] == s1F[idx]) matches++;   // 変更後に一致したらmatchesを増やす

        // --- ウィンドウから出ていく文字（左端）の処理 ---
        idx = s2.charAt(i - m) - 'a';
        // 入る文字と同じ手順: 変更前の判定→値の変更→変更後の判定
        if (winF[idx] == s1F[idx]) matches--;   // 変更前に一致していたらmatchesを減らす
        winF[idx]--;                              // ウィンドウから出るので頻度を1減らす
        if (winF[idx] == s1F[idx]) matches++;   // 変更後に一致したらmatchesを増やす

        // 全26文字の頻度が一致していれば順列が見つかったのでtrueを返す
        if (matches == 26) return true;
    }

    // s2の末尾までスライドしてもmatches==26にならなかったのでfalseを返す
    return false;
}
```
