# Counting Distinct Subsequences — 文字列sの中にtと一致する部分列がいくつあるかを数える

## 問題の本質

2つの文字列 `s` と `t` が与えられる。`s` から0個以上の文字を削除して（残った文字の相対順序は変えずに）`t` と一致する部分列を作る方法が何通りあるかを数えて返す。

## 核心のアイデア

`s` の各文字について「`t` のマッチングに使うか使わないか」の2択がある。この選択の累積を1次元配列で管理し、後ろから更新することで「使う場合」と「使わない場合」の加算を正しく行える。

## 思考プロセス

1. **部分列のマッチングは選択の積み重ねである**: `s` の i 番目の文字が `t` の j 番目の文字と一致するとき、「この文字を `t[j]` のマッチに使う」か「使わずにスキップする」かの2つの選択肢がある。両方の場合の数を合計すれば全パターンが求まる
2. **DPの状態を定義する**: `dp[j]` を「`t` の先頭 j 文字に一致する `s` の部分列の数」と定義する。最終的に `dp[n]`（n は `t` の長さ）が答えになる
3. **ベースケースを考える**: `t` の先頭0文字（空文字列）に一致する部分列は、どんな `s` に対しても「何も選ばない」という1通りが存在する。よって `dp[0] = 1` である
4. **遷移式を導出する**: `s[i-1] == t[j-1]` のとき、`dp[j]` には2つの寄与がある。「`s[i-1]` を使わない場合」は既存の `dp[j]` がそのまま残り、「`s[i-1]` を使う場合」は `dp[j-1]`（1つ前の文字までマッチ済みの数）が加算される。よって `dp[j] += dp[j-1]` となる。文字が一致しないときは `dp[j]` は変化しない（スキップ一択）
5. **更新順序を逆順にする理由**: `dp[j] += dp[j-1]` では更新前の `dp[j-1]` が必要である。もし j を小さい方から更新すると、`dp[j-1]` が先に書き換わってしまい、古い値が失われる。j を大きい方から小さい方へ逆順に更新すれば、`dp[j-1]` はまだ更新前の値を保持しているので正しく計算できる
6. **最終的に返すもの**: `s` の全文字を走査し終えた後の `dp[n]` が、`s` の中に `t` と一致する部分列がいくつあるかの答えである

## 前提知識

### 部分列（Subsequence）とは

元の文字列から0個以上の文字を削除し、残った文字の相対的な順序を保ったまま構成される文字列。部分文字列（Substring）とは異なり、連続している必要はない。

```
s = "rabbbit", t = "rabbit"
部分列の例: s の 1,2,3,5,6,7 番目の文字を選ぶ → "rabbit" ✓
部分列の例: s の 1,2,4,5,6,7 番目の文字を選ぶ → "rabbit" ✓
部分列の例: s の 1,3,4,5,6,7 番目の文字を選ぶ → "rabbit" ✓
→ 合計3通り
```

### 1次元DPの逆順更新とは

2次元DPテーブル `dp[i][j]` を1次元配列 `dp[j]` に圧縮する手法。現在の行の計算に前の行の値だけが必要な場合、1次元配列を使い回すことで空間計算量を削減できる。ただし、`dp[j]` の更新で `dp[j-1]`（前の行の値）が必要なとき、j を昇順に更新すると `dp[j-1]` が現在の行の値で上書きされてしまう。j を降順（大→小）に更新することで、まだ上書きされていない前の行の `dp[j-1]` を正しく参照できる。

```java
// 2次元DP（元の形）
dp[i][j] = dp[i-1][j] + dp[i-1][j-1];

// 1次元DPに圧縮（逆順更新）
for (int j = n; j >= 1; j--) {   // 大きい方から更新する
    dp[j] += dp[j - 1];          // dp[j-1] はまだ前の行の値を保持している
}
```

## 計算量

| | 値 |
|---|---|
| Time | O(m × n) — sの各文字（m個）に対してtの各文字（n個）を走査する |
| Space | O(n) — 長さ n+1 の1次元配列のみを使用する |

## コード

```java
// 入力: 文字列 s（長さ m）と文字列 t（長さ n）
// 出力: s の部分列のうち t と一致するものの個数を int で返す
public int numDistinct(String s, String t) {
    int m = s.length();
    int n = t.length();

    // dp[j] = tの先頭j文字に一致するsの部分列の数
    // インデックス 0〜n の n+1 個の状態を管理するため、サイズは n+1 にする
    int[] dp = new int[n + 1];

    // 空文字列に一致する部分列は常に1通り（何も選ばない）
    // このベースケースは s のどの位置から始めても成り立つ
    dp[0] = 1;

    // sの各文字を順に考慮する（i は s の何文字目まで考慮したかを表す）
    for (int i = 1; i <= m; i++) {
        // j を逆順（大→小）に走査する
        // 理由: dp[j] += dp[j-1] の計算で更新前の dp[j-1] を参照する必要がある
        // 昇順に更新すると dp[j-1] が先に書き換わり、前の行の値が失われてしまう
        for (int j = n; j >= 1; j--) {
            // i, j は1始まりだが、文字列のインデックスは0始まりなので i-1, j-1 でアクセスする
            if (s.charAt(i - 1) == t.charAt(j - 1))
                // 一致する場合: dp[j]（使わない場合の数）に dp[j-1]（使う場合の数）を加算する
                // この加算により「使う」と「使わない」の両方の選択肢の合計が dp[j] に蓄積される
                dp[j] += dp[j - 1];
            // 一致しない場合: 何もしない（s[i-1] は t[j-1] のマッチに使えないのでスキップ一択）
        }
    }

    // dp[n] は s 全体の中で t 全体に一致する部分列の個数を保持している
    return dp[n];
}
```
