# Counting Connected Components in an Undirected Graph — 無向グラフの連結成分の数を数える

## 問題の本質

`0` から `n-1` までのラベルが付いた `n` 個のノードと、無向辺のリスト `edges` が与えられる。グラフ内の**連結成分（connected component）の数**を整数で返す。連結成分とは、辺をたどって互いに到達可能なノードの集まりである。

## 核心のアイデア

最初に各ノードを独立した連結成分とみなし、辺を1本ずつ処理して両端のノードが属するグループを統合していく。すべての辺を処理した後に残っているグループの数が、連結成分の数である。

## 思考プロセス

1. **辺でつながるノードは同じグループに属する**: 連結成分とは「辺をたどって到達可能なノードの集合」なので、辺で結ばれた2つのノードは必ず同じ連結成分に属する。すべての辺について「両端のノードを同じグループにまとめる」操作を繰り返せば、最終的に連結成分が求まる
2. **グループの管理にはUnion-Findが適している**: 「2つの要素を同じグループに統合する（union）」と「ある要素がどのグループに属するかを調べる（find）」を高速に行うデータ構造がUnion-Findである。各ノードに「親ノード」を持たせ、根（root）が同じノード同士を同一グループとみなす
3. **初期状態では各ノードが自分自身を親に持つ**: `parent[i] = i` と初期化することで、最初はn個のノードがそれぞれ独立したグループ（連結成分）になる。初期の連結成分の数は `n` である
4. **辺を処理するたびにunionを行い、統合が起きたら成分数を減らす**: 各辺 `[a, b]` について、`a` の根と `b` の根を求める。根が異なれば2つは別のグループなので、一方の根をもう一方の根の子にして統合し、連結成分の数を1つ減らす。根が同じなら既に同じグループなので何もしない
5. **経路圧縮とランクで高速化する**: findの際に経路圧縮（path compression）を行い、訪問したノードの親を直接根に付け替える。unionの際にランク（木の高さの上限）を比較し、低い木を高い木の下に付ける（union by rank）。これにより、findの計算量がほぼO(1)（正確にはO(α(V))）になる
6. **すべての辺を処理した後の `components` が答えである**: 初期値 `n` から、unionが成功するたびに1ずつ減らした結果が、最終的な連結成分の数になる

## 前提知識

### Union-Find（素集合データ構造）とは

要素をグループに分けて管理するデータ構造。「2つの要素を同じグループに統合する（union）」と「ある要素が属するグループの代表（根）を求める（find）」の2つの操作を提供する。`parent` 配列で各要素の親を記録し、根まで親をたどることでグループの代表を特定する。

```java
int[] parent = new int[n];   // parent[i]はノードiの親ノードを保存する
for (int i = 0; i < n; i++)
    parent[i] = i;            // 初期状態: 各ノードが自分自身を親に持つ（独立したグループ）
```

### 経路圧縮（Path Compression）とは

findの再帰過程で、訪問した全ノードの親を直接根に付け替える最適化手法。次回以降のfindが即座に根を返すようになり、木が平坦化されることで計算量がほぼO(1)に改善される。

```java
int find(int[] parent, int x) {
    if (parent[x] != x)
        parent[x] = find(parent, parent[x]);  // 再帰で根を見つけ、親を根に付け替える
    return parent[x];                          // 根を返す
}
```

### ランク（Rank）によるunionとは

union時に木の高さの上限（ランク）を比較し、ランクが低い木をランクが高い木の下に付ける手法。木の高さの増加を抑えることで、findの効率を維持する。ランクが等しい場合のみ、統合先のランクを1つ増やす。

```java
int[] rank = new int[n];     // rank[i]はノードiを根とする木の高さの上限（初期値は0）
// ランクが高い方を親にする → 木が深くなりにくい
if (rank[r1] > rank[r2])
    parent[r2] = r1;         // r2の木をr1の下に付ける
```

### α（アッカーマン関数の逆関数）とは

Union-Findの計算量に現れる関数。実用的な入力サイズではα(V)は常に5以下であり、事実上の定数とみなせる。そのため、Union-Findの各操作はほぼO(1)で動作する。

## 計算量

| | 値 |
|---|---|
| Time | O(V + E · α(V)) — 初期化にO(V)、各辺についてfindとunionを行うがα(V)はほぼ定数なので実質O(V + E) |
| Space | O(V) — parent配列とrank配列にそれぞれV個の要素を保存する |

## コード

```java
// 入力: ノード数 n と辺のリスト edges（各辺は2要素の配列 [a, b]）
// 出力: 連結成分の数を整数で返す

// 経路圧縮付きのfind関数: ノードxが属するグループの根を返す
int find(int[] parent, int x) {
    if (parent[x] != x)
        // 再帰的に根を見つけ、親を直接根に付け替える（経路圧縮）
        // これにより次回以降のfindが即座に根を返すようになる
        parent[x] = find(parent, parent[x]);
    return parent[x];
}

int countComponents(int n, int[][] edges) {
    // 各ノードの親を保存する配列。parent[i] = i で初期化し、各ノードを独立したグループにする
    int[] parent = new int[n];
    // 各ノードを根とする木の高さの上限を保存する配列（union時にどちらの下に付けるか決定に使用）
    int[] rank = new int[n];
    for (int i = 0; i < n; i++)
        parent[i] = i;

    // 初期状態では各ノードが独立した連結成分なので、成分数はn
    int components = n;

    // 辺を1本ずつ走査し、両端のノードが属するグループを統合していく
    for (int[] e : edges) {
        // 辺の両端のノードが属するグループの根を求める（経路圧縮により訪問ノードの親も根に付け替わる）
        int r1 = find(parent, e[0]);
        int r2 = find(parent, e[1]);

        // 根が異なれば別のグループなので統合する（根が同じなら既に同じグループなので何もしない）
        if (r1 != r2) {
            // ランクを比較し、低い方を高い方の下に付ける（木の高さの増加を抑える）
            if (rank[r1] > rank[r2])
                parent[r2] = r1;
            else if (rank[r1] < rank[r2])
                parent[r1] = r2;
            else {
                // ランクが等しい場合、r2をr1の下に付けてr1のランクを1つ増やす
                parent[r2] = r1;
                rank[r1]++;
            }
            // 2つのグループが1つに統合されたので成分数を1つ減らす
            components--;
        }
    }
    // すべての辺を処理した後のcomponentsが連結成分の数
    return components;
}
```
