# Finding a Valid Order to Complete All Courses — 全コースを完了できる有効な履修順序を求める

## 問題の本質

0から `numCourses - 1` までのラベルが付いたコースと、前提条件のペア `[a, b]`（コース `b` をコース `a` より先に履修する必要がある）の配列が与えられる。全コースを完了できる**有効な履修順序**を配列で返す。有効な順序が存在しない場合（循環依存がある場合）は空の配列を返す。

## 核心のアイデア

前提条件の依存関係は有向グラフで表現でき、有効な履修順序はそのグラフのトポロジカルソートに対応する。入次数が0のノード（前提条件がないコース）から順に処理し、処理済みノードの依存を取り除いていけば、循環がない限り全ノードを正しい順序で並べられる。

## 思考プロセス

1. **依存関係をグラフとして捉える**: 前提条件 `[a, b]` は「`b` → `a`」という有向辺を意味する。全ての前提条件を有向グラフの辺として表現すれば、有効な履修順序はこのグラフのトポロジカルソートになる
2. **どのコースから開始できるかを判定したい**: 前提条件が一つもないコース、つまり入次数（そのノードに入ってくる辺の数）が0のコースは、すぐに履修できる。入次数を各ノードについて計算しておけば、開始可能なコースをO(1)で判定できる
3. **開始可能なコースを処理した後の影響を反映する**: あるコースを履修済みにすると、そのコースを前提条件としていた他のコースの「残りの前提条件数」が1つ減る。これは入次数のデクリメントとして表現できる。デクリメントの結果、入次数が0になったコースは新たに履修可能になる
4. **BFSで処理順序を管理する**: 入次数が0のコースをキューに入れ、キューから取り出すたびにそのコースを結果配列に追加し、隣接ノードの入次数をデクリメントする。デクリメントの結果0になったノードをキューに追加する。この繰り返しがKahn'sアルゴリズムである
5. **循環依存の検出**: 循環があると、循環内の全ノードの入次数は永遠に0にならない。そのため、処理したコース数が `numCourses` に満たなければ循環が存在すると判定できる
6. **最終的に返すもの**: 処理したコース数が `numCourses` と一致すれば結果配列を返し、一致しなければ空の配列を返す

## 前提知識

### トポロジカルソートとは

有向非巡回グラフ（DAG）の全ノードを、全ての辺が左から右へ向くように一列に並べること。辺 `u → v` があるとき、並び順で `u` は必ず `v` より前に来る。循環がある場合はトポロジカルソートは不可能である。

### 入次数（in-degree）とは

あるノードに入ってくる辺の数。入次数が0のノードは、他のどのノードにも依存していないため、最初に処理できる。

```java
int[] indegree = new int[numCourses];  // 各ノードの入次数を0で初期化
indegree[a]++;  // ノードaに辺が1本入るので入次数を1増やす
--indegree[next];  // ノードnextの入次数を1減らす（前提条件を1つ解消）
```

### 隣接リスト（Adjacency List）とは

グラフの各ノードについて、そのノードから辺が出ている先のノードをリストで管理するデータ構造。`graph.get(u)` でノード `u` から到達可能な全ノードを取得できる。

```java
List<List<Integer>> graph = new ArrayList<>();       // グラフ全体を保持するリスト
for (int i = 0; i < n; i++) graph.add(new ArrayList<>());  // 各ノードに空のリストを割り当てる
graph.get(u).add(v);   // ノードuからノードvへの辺を追加する
graph.get(u);           // ノードuの全隣接ノードを取得する → [v, ...]
```

### Queue（キュー）とは

先入れ先出し（FIFO）のデータ構造。BFSでは処理待ちのノードをキューで管理する。

```java
Queue<Integer> queue = new LinkedList<>();  // 空のキューを作成
queue.offer(0);   // キューの末尾に要素0を追加する
queue.poll();      // キューの先頭から要素を取り出して返す → 0
queue.isEmpty();   // キューが空かをbooleanで返す → true
```

## 計算量

| | 値 |
|---|---|
| Time | O(V + E) — 全ノード（コース）と全辺（前提条件）を各1回ずつ処理する |
| Space | O(V + E) — 隣接リストに全辺を、入次数配列とキューと結果配列に全ノードを保存する |

## コード

```java
// 入力: 整数 numCourses（コースの総数）と二次元整数配列 prerequisites（前提条件のペアの配列）
// 出力: 全コースの有効な履修順序を格納した int[] を返す。有効な順序が存在しなければ空の int[] を返す
public int[] findOrder(int numCourses, int[][] prerequisites) {
    // 隣接リストを作成し、各コースに空のリストを割り当てる
    // 各インデックスがコース番号に対応し、そのコースの履修後に受講可能になるコースのリストを保持する
    List<List<Integer>> graph = new ArrayList<>();
    // 入次数配列: 各コースの未履修の前提条件の数を表す
    int[] indegree = new int[numCourses];
    for (int i = 0; i < numCourses; i++)
        graph.add(new ArrayList<>());

    // 前提条件から辺を作成し、入次数を計算する
    // 各ペア [a, b] について辺 b → a を作成し、コース a はコース b に依存していることを記録する
    for (int[] pre : prerequisites) {
        graph.get(pre[1]).add(pre[0]);  // 辺 pre[1] → pre[0] を追加する
        indegree[pre[0]]++;  // コース pre[0] の入次数を1増やす
    }

    // 入次数が0のコース（前提条件なし）をキューに追加する
    // これらは最初に履修できるコースである
    Queue<Integer> queue = new LinkedList<>();
    for (int i = 0; i < numCourses; i++)
        if (indegree[i] == 0) queue.offer(i);

    // 結果配列と書き込み位置を初期化する
    int[] result = new int[numCourses];
    int idx = 0;

    while (!queue.isEmpty()) {
        // キューからコースを取り出し、履修順序に確定する
        int course = queue.poll();
        result[idx++] = course;

        // course の全隣接ノード next の入次数を1減らす
        // これは next の前提条件の一つである course が履修済みになったことを反映している
        for (int next : graph.get(course))
            // デクリメントの結果0になった場合、next の全前提条件が完了したのでキューに追加する
            if (--indegree[next] == 0)
                queue.offer(next);
    }

    // 全コースを処理できたか判定する
    // idx が numCourses に満たなければ循環依存が存在するため空配列を返す
    return idx == numCourses ? result : new int[0];
}
```
