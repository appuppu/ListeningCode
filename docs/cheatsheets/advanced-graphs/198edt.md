# Finding the Minimum Time to Swim Across a Grid — グリッドを泳いで渡る最短時間を求める

## 問題の本質

n×nのグリッドが与えられ、各セルには0からn²-1までの一意な標高値が入っている。あるセルから隣接セル（上下左右）へ泳いで移動できるのは、現在の時刻が**両方のセルの標高以上**であるときのみ。左上(0,0)から右下(n-1,n-1)まで到達するのに必要な**最小の時刻**を求める。開始時刻はgrid[0][0]の値である。

## 核心のアイデア

経路上で通過するセルの標高の**最大値**が、その経路に必要な時刻となる。最小ヒープを使って「現在到達可能なセルのうち、必要時刻が最も小さいセル」から順に探索すれば、最初にゴールに到達した時点の時刻が最適解である。

## 思考プロセス

1. **移動条件を言い換える**: セルAからセルBに移動するには「時刻 ≥ max(A, B)」が必要である。つまり、スタートからゴールまでの経路全体で必要な時刻は「経路上の全セルの標高の最大値」に等しい。したがって問題は「経路上の最大標高が最小になる経路を見つける」ことに帰着する
2. **最短経路問題との類似性に気づく**: 通常のDijkstraは「経路上の辺の重みの合計」を最小化するが、この問題では「経路上のセルの標高の最大値」を最小化する。合計の代わりに最大値を使うことで、Dijkstraの枠組みをそのまま適用できる
3. **優先度付きキューで最小時刻のセルから展開する**: 最小ヒープ（PriorityQueue）にセルを「そこに到達するために必要な時刻」で格納する。常に必要時刻が最も小さいセルから展開することで、各セルに最初に到達した時点の時刻が最適であることが保証される
4. **隣接セルへの必要時刻を計算する**: 現在のセル(r,c)の必要時刻が`time`であるとき、隣接セル(nr,nc)への必要時刻は`Math.max(time, grid[nr][nc])`で計算する。これは「ここまでの経路上の最大標高」と「次のセルの標高」のうち大きい方が、新しい経路の必要時刻となるためである
5. **訪問済み管理で重複を防ぐ**: 最小ヒープから取り出されたセルは、その時点で最適な時刻が確定している。訪問済み配列`vis`でマークし、同じセルを再度処理しないようにする。これはDijkstraの確定済みノードと同じ考え方である
6. **ゴール到達時に即座に返す**: ヒープから取り出したセルが(n-1, n-1)であれば、そのときの`time`が最小時刻である。最小ヒープにより最小の時刻から順に処理しているため、最初にゴールに到達した時点が最適解となる

## 前提知識

### PriorityQueue（最小ヒープ）とは

要素を優先度順に取り出せるデータ構造。デフォルトでは最小値が最優先で取り出される。挿入・取り出しともにO(log n)の計算量で動作する。Dijkstra法では「未確定ノードの中で最小コストのものを選ぶ」操作を効率的に行うために使う。

```java
// int[]の第0要素で昇順に並べる最小ヒープを作成する
PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[0] - b[0]);
pq.offer(new int[]{5, 0, 0});   // 要素を追加する（O(log n)）
pq.offer(new int[]{3, 1, 0});   // 要素を追加する
int[] min = pq.poll();          // 最小要素を取り出して削除する → {3, 1, 0}
boolean empty = pq.isEmpty();   // キューが空かどうかを判定する → false
```

### Dijkstra法の変形とは

通常のDijkstra法は辺の重みの**合計**を最小化するが、この問題では経路上の標高の**最大値**を最小化する。距離の更新式を`dist[next] = dist[cur] + weight`から`dist[next] = max(dist[cur], grid[next])`に変えるだけで、Dijkstraの正当性（最小ヒープから取り出した時点で最適が確定する性質）がそのまま保たれる。

### 4方向の隣接セル探索

グリッド上のセル(r,c)の上下左右の隣接セルは、方向ベクトル`{{0,1},{0,-1},{1,0},{-1,0}}`を加算して列挙する。範囲外チェック（0 ≤ nr < n かつ 0 ≤ nc < n）を行い、有効なセルのみを処理する。

```java
int[][] dir = {{0,1},{0,-1},{1,0},{-1,0}};  // 右・左・下・上の4方向
for (int[] d : dir) {
    int nr = r + d[0];  // 隣接セルの行
    int nc = c + d[1];  // 隣接セルの列
    if (nr >= 0 && nr < n && nc >= 0 && nc < n) {
        // (nr, nc) は有効な隣接セル
    }
}
```

## 計算量

| | 値 |
|---|---|
| Time | O(n² log n) — n²個のセルをそれぞれ最大1回ヒープに出し入れする。ヒープ操作1回あたりO(log n²) = O(log n) |
| Space | O(n²) — 訪問済み配列とヒープにそれぞれ最大n²個のセルを保持する |

## コード

```java
// 入力: n×nの整数配列 grid（各セルに0からn²-1までの一意な標高値が入っている）
// 出力: 左上(0,0)から右下(n-1,n-1)まで到達するために必要な最小時刻を int で返す
int swimInWater(int[][] grid) {
    int n = grid.length;
    // 各セルの最適時刻が確定済みかを管理する訪問済み配列（vis[r][c] = trueなら確定済み）
    boolean[][] vis = new boolean[n][n];
    // 必要時刻が小さい順に取り出す最小ヒープ（要素: {時刻, 行, 列}）
    // 比較関数 (a,b)->a[0]-b[0] により第0要素（必要時刻）の昇順で取り出される
    PriorityQueue<int[]> pq =
        new PriorityQueue<>(
            (a, b) -> a[0] - b[0]);
    // スタート地点をヒープに追加し、訪問済みにする
    // 第0要素が必要時刻、第1要素が行、第2要素が列
    pq.offer(new int[]
        {grid[0][0], 0, 0});
    vis[0][0] = true;
    // 上下左右の4方向ベクトル
    int[][] dir =
        {{0,1},{0,-1},{1,0},{-1,0}};
    while (!pq.isEmpty()) {
        // 必要時刻が最小のセルを取り出す（最小ヒープの性質により、この時点で最適時刻が確定）
        int[] cur = pq.poll();
        int time = cur[0];
        int r = cur[1], c = cur[2];
        // ゴールに到達したら、その時刻が最適解（最小時刻から順に処理しているため最初の到達が最適）
        if (r == n-1 && c == n-1)
            return time;
        // 4方向の隣接セルを探索する
        for (int[] d : dir) {
            int nr = r+d[0];
            int nc = c+d[1];
            // 範囲内かつ未訪問のセルのみ処理する
            if (nr >= 0 && nr < n
                && nc >= 0 && nc < n
                && !vis[nr][nc]) {
                // 注意: ヒープに追加する時点で訪問済みにすることで、同じセルが複数回ヒープに追加されることを防ぐ
                vis[nr][nc] = true;
                // 経路上の最大標高が必要時刻となる（「ここまでの最大標高」と「次のセルの標高」の大きい方）
                int nt = Math.max(
                    time,grid[nr][nc]);
                pq.offer(new int[]
                    {nt, nr, nc});
            }
        }
    }
    // 問題の制約上グリッドは連結なのでここには到達しない
    return -1;
}
```
