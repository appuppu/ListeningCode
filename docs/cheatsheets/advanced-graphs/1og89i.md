# Reconstructing a Flight Itinerary — 航空チケットから辞書順最小の旅程を再構築する

## 問題の本質

出発空港と到着空港のペアで表された航空チケットのリストが与えられる。JFKから出発して全てのチケットをちょうど1回ずつ使い切る旅程を再構築する。有効な旅程が複数存在する場合は、辞書順で最小のものを返す。

## 核心のアイデア

全ての辺（チケット）をちょうど1回ずつ通るオイラー路の問題である。各空港の行き先をPriorityQueueで管理すれば辞書順最小が自動的に保証され、Hierholzerのアルゴリズムで後ろから旅程を構築すれば行き止まりを正しく処理できる。

## 思考プロセス

1. **全チケットを1回ずつ使い切る = オイラー路**: 各チケットは有向グラフの辺であり、全ての辺をちょうど1回通るパスを求める問題はオイラー路（Eulerian Path）の問題に帰着する
2. **辞書順最小を保証するにはソートが必要**: 各空港から複数の行き先がある場合、辞書順で小さい方を先に選びたい。各空港の行き先をPriorityQueue（最小ヒープ）に格納すれば、`poll()`するだけで常に辞書順最小の行き先が得られる
3. **単純な貪欲法では行き止まりに対処できない**: 辞書順最小を常に選ぶと、未使用の辺が残っているのに先に行き止まりに到達してしまう場合がある。例えばJFK→A→JFK→B のチケットがあるとき、JFKからAを先に選ぶとA→JFK→Bと進めるが、Bを先に選ぶとBで行き止まりになる
4. **Hierholzerのアルゴリズムで後ろから構築する**: DFSで行き先がなくなった（行き止まりに到達した）ノードを結果リストの**先頭**に追加する。こうすると行き止まりは旅程の末尾に配置され、残りの辺は再帰の巻き戻し時に正しい順序で先頭に追加されていく
5. **再帰DFSの動作**: 現在のノードからPriorityQueueで辞書順最小の行き先を取り出し、再帰的にDFSする。行き先がなくなったら結果リストの先頭に現在のノードを追加する。LinkedListの`addFirst`を使えばO(1)で先頭追加ができる
6. **最終的に返すもの**: 全てのDFSが完了した後、結果リスト（LinkedList）をそのまま返す。リストにはJFKから始まる辞書順最小の旅程が格納されている

## 前提知識

### PriorityQueue（優先度付きキュー）とは

要素を追加すると自動的にソートされ、取り出し時に常に最小の要素が得られるデータ構造。内部はヒープで実装されており、追加・取り出しともにO(log n)で動作する。

```java
PriorityQueue<String> pq = new PriorityQueue<>();  // 文字列の自然順序（辞書順）で最小ヒープを作成
pq.offer("SFO");       // "SFO"を追加する
pq.offer("ATL");       // "ATL"を追加する
pq.poll();             // 最小の要素"ATL"を取り出して削除する → "ATL"
pq.isEmpty();          // キューが空かをbooleanで返す → false（"SFO"が残っている）
```

### computeIfAbsent とは

HashMapのキーが存在しない場合にのみ、指定した関数で値を生成して登録し、その値を返すメソッド。キーが既に存在する場合は既存の値をそのまま返す。`get`して`null`チェックして`put`する3ステップを1行で書ける。

```java
Map<String, PriorityQueue<String>> graph = new HashMap<>();
// "JFK"キーが存在しなければ新しいPriorityQueueを作成して登録し、そのPriorityQueueを返す
graph.computeIfAbsent("JFK", k -> new PriorityQueue<>()).offer("SFO");
// "JFK"キーが既に存在するので、既存のPriorityQueueを返す（新規作成しない）
graph.computeIfAbsent("JFK", k -> new PriorityQueue<>()).offer("ATL");
```

### LinkedList の addFirst とは

リストの先頭に要素をO(1)で追加するメソッド。通常の`add`（末尾追加）とは異なり、既存の要素を後ろにずらすことなく先頭に挿入できる。Hierholzerのアルゴリズムで逆順に結果を構築する際に使用する。

```java
LinkedList<String> result = new LinkedList<>();
result.addFirst("JFK");   // result: ["JFK"]
result.addFirst("ATL");   // result: ["ATL", "JFK"]
result.addFirst("SFO");   // result: ["SFO", "ATL", "JFK"]
```

### Hierholzerのアルゴリズムとは

オイラー路（全ての辺をちょうど1回通るパス）を求めるアルゴリズム。DFSで辺を消費しながら進み、行き止まりに到達したノードを結果の先頭に追加する。全ての辺を使い切った後、結果リストにはオイラー路が正しい順序で格納される。行き止まりを旅程の末尾に自然に配置できる点がこの問題に適している。

## 計算量

| | 値 |
|---|---|
| Time | O(E log E) — 各チケット（辺）をPriorityQueueに追加・取り出しする際にlog Eのコストがかかる |
| Space | O(V + E) — グラフの隣接リストに全ての辺を保存し、再帰スタックは最大で辺の数だけ深くなる |

## コード

```java
// 入力: 航空チケットのリスト tickets（各チケットは [出発空港, 到着空港] の文字列ペア）
// 出力: JFKから始まる辞書順最小の旅程を List<String> で返す
public List<String> findItinerary(List<List<String>> tickets) {
    // キー=出発空港、バリュー=到着空港を辞書順に管理するPriorityQueue
    // PriorityQueueを使うことで、取り出し時に常に辞書順最小の行き先が得られる
    Map<String, PriorityQueue<String>> graph = new HashMap<>();

    // 全チケットからグラフを構築する
    // computeIfAbsentにより、srcキーが初出なら新しいPriorityQueueを作成、既存ならそのまま取得する
    for (List<String> t : tickets) {
        graph.computeIfAbsent(t.get(0), k -> new PriorityQueue<>())
             .offer(t.get(1));
    }

    // 結果を格納するLinkedList（addFirstでO(1)の先頭追加を行うため）
    LinkedList<String> result = new LinkedList<>();

    // JFKからDFSを開始する
    dfs("JFK", graph, result);
    return result;
}

void dfs(String curr,
          Map<String, PriorityQueue<String>> graph,
          LinkedList<String> result) {
    // 現在の空港から行ける行き先のPriorityQueueを取得する
    PriorityQueue<String> dests = graph.get(curr);

    // 行き先が存在する間、辞書順最小の行き先を取り出してDFSする
    // 注意: poll()は要素を削除するため、同じ辺（チケット）を2回通ることはない
    while (dests != null && !dests.isEmpty()) {
        dfs(dests.poll(), graph, result);
    }

    // 行き止まりに到達したら、結果リストの先頭に現在の空港を追加する
    // 先頭に追加することで、行き止まりのノードは旅程の末尾側に配置され、
    // 後から追加されるノードが旅程の前方に正しく配置される
    result.addFirst(curr);
}
```
