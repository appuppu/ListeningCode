# Finding the Minimum in a Rotated Sorted Array — 回転されたソート済み配列から最小値を見つける

## 問題の本質

昇順にソートされたユニークな整数の配列が、1回以上n回以下回転されている。この回転済み配列の中から**最小の要素**を見つけて返す。回転とは、配列の末尾の要素を先頭に移動する操作であり、元のソート順が途中で「折れ曲がる」ピボットが存在する。

## 核心のアイデア

回転済みソート配列では、最小値はソート順が崩れる「ピボット」の位置にある。中央の要素と右端の要素を比較すれば、最小値が左半分と右半分のどちらに存在するかを1回の比較で判定でき、二分探索で O(log n) で見つけられる。

## 思考プロセス

1. **最小値はピボットの位置にある**: 回転されたソート済み配列は、「大きい部分列」と「小さい部分列」の2つのソート済み部分に分かれる。最小値は「小さい部分列」の先頭、つまりピボットの位置に存在する。このピボットを探すことが問題の本質である
2. **線形探索ではなく二分探索を使いたい**: 配列は完全にソートされてはいないが、2つのソート済み部分に分かれているという構造がある。この構造を利用すれば、毎回半分を捨てる二分探索が適用できる
3. **中央の要素と右端の要素を比較する**: `nums[mid] > nums[right]` が成り立つ場合、midからrightの間にピボット（ソート順の崩れ）が存在するので、最小値は右半分にある。逆に `nums[mid] <= nums[right]` の場合、midからrightはソート済みであり、最小値はmid以左（mid自身を含む）にある
4. **左端ではなく右端と比較する理由**: 左端と比較すると、配列が回転されていない場合（全体がソート済み）に正しく判定できない。右端と比較すれば、回転の有無にかかわらず最小値の位置を正しく絞り込める
5. **探索範囲の更新方法**: `nums[mid] > nums[right]` のとき、midは最小値ではないことが確定するので `left = mid + 1` とする。そうでないとき、midが最小値の可能性があるので `right = mid` とする（midを除外しない）
6. **ループの終了条件**: `left < right` の間ループし、`left == right` になった時点で探索範囲が1要素に絞られる。その要素 `nums[left]` が最小値である

## 前提知識

### 回転されたソート済み配列とは

昇順ソート済み配列 `[1, 2, 3, 4, 5]` を右に2回回転すると `[4, 5, 1, 2, 3]` になる。配列は2つのソート済み部分列 `[4, 5]` と `[1, 2, 3]` に分かれ、その境界がピボットである。

```
元の配列:    [1, 2, 3, 4, 5]
2回回転後:   [4, 5, 1, 2, 3]
                   ↑ ピボット（最小値）
```

### 二分探索の基本構造

探索範囲を毎回半分に絞ることで、O(log n) で目的の要素を見つける手法。leftとrightの2つのポインタで探索範囲を管理し、中央の要素を基準に範囲を更新する。

```java
int left = 0;
int right = nums.length - 1;
int mid = left + (right - left) / 2;  // オーバーフローを防ぐ中央値の計算
```

### `left + (right - left) / 2` とは

中央のインデックスを計算する式。`(left + right) / 2` でも同じ結果だが、leftとrightが大きい値のとき加算でintの最大値を超える可能性がある。この式はその**オーバーフローを防ぐ**安全な書き方である。

## 計算量

| | 値 |
|---|---|
| Time | O(log n) — 毎回探索範囲を半分に絞るため、最大でlog n回の比較で最小値が見つかる |
| Space | O(1) — left, right, midの3つの変数のみを使用し、追加のデータ構造は不要 |

## コード

```java
// 入力: 回転されたソート済みのユニークな整数配列 nums
// 出力: 配列内の最小値を int で返す
public int findMin(int[] nums) {
    // 探索範囲の両端を初期化する。この2つの変数が探索範囲の両端を表す
    int left = 0;
    int right = nums.length - 1;

    // left == right になったとき探索範囲が1要素に絞られ、その要素が最小値である
    while (left < right) {
        // (left + right) / 2 ではなくこの式を使うのは、整数オーバーフローを防ぐため
        int mid = left + (right - left) / 2;

        // 中央の要素が右端より大きい場合、midとrightの間にピボット（ソート順の崩れ）が存在する
        if (nums[mid] > nums[right]) {
            // 最小値はmidより右側にある。midは右端より大きいので最小値ではなく、除外できる
            left = mid + 1;
        } else {
            // midからrightまではソート済み。最小値はmid以左（mid自身を含む）にある
            // mid自身が最小値である可能性があるため、midを探索範囲から除外しない
            right = mid;
        }
    }

    // left == right となっており、探索範囲が1要素に絞られたので、その要素が最小値である
    return nums[left];
}
```
