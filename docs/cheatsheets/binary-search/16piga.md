# Finding the Median of Two Sorted Arrays — 2つのソート済み配列を合併したときの中央値を求める

## 問題の本質

2つのソート済み整数配列 `n1` と `n2` が与えられる。2つの配列を合併した場合の**中央値**を求める。解法は全要素数に対して対数時間で動作しなければならない。

## 核心のアイデア

2つのソート済み配列の中央値を求めることは、「左半分」と「右半分」に正しく分割する境界を見つけることと等しい。短い方の配列に対して二分探索を行い、分割位置を決めれば、もう一方の配列の分割位置も自動的に決まる。

## 思考プロセス

1. **中央値は「左半分の最大値」と「右半分の最小値」で決まる**: 合併後の配列をソート済みのまま左右に二等分できれば、中央値は左半分の最大値（奇数個なら）、または左半分の最大値と右半分の最小値の平均（偶数個なら）で求まる。つまり、全要素をソートせずとも、正しい分割位置さえ見つければよい
2. **分割位置は片方の配列で決めればもう片方は自動的に決まる**: 左半分に合計 `half = (m + n + 1) / 2` 個の要素を入れると決めると、配列 `n1` から `cut1` 個取れば、配列 `n2` からは `cut2 = half - cut1` 個取る必要がある。つまり、`cut1` だけを探索すればよい
3. **正しい分割の条件は「交差比較」で判定できる**: 分割が正しいとは、左半分の全要素が右半分の全要素以下であること。各配列内はソート済みなので、交差する部分だけ確認すればよい。具体的には `n1` の左端末尾 `l1` ≤ `n2` の右端先頭 `r2`、かつ `n2` の左端末尾 `l2` ≤ `n1` の右端先頭 `r1` が成り立てば正しい分割である
4. **二分探索で `cut1` を効率的に探す**: `cut1` の範囲は `0` から `m` まで。`l1 > r2` なら `n1` から取りすぎているので `cut1` を減らし、`l2 > r1` なら `n1` から取らなすぎているので `cut1` を増やす。この判定により二分探索が成立する
5. **短い方の配列で探索する理由**: 二分探索の範囲は `0` から `m`（配列の長さ）なので、短い方の配列を選べば探索範囲が小さくなり、計算量が `O(log(min(m, n)))` になる
6. **境界の処理には番兵値を使う**: `cut1 = 0`（`n1` から1つも取らない）や `cut1 = m`（`n1` を全部取る）のとき、存在しない要素にアクセスすることになる。`Integer.MIN_VALUE` と `Integer.MAX_VALUE` を番兵値として使えば、比較条件が常に正しく動作する

## 前提知識

### 中央値（Median）とは

ソート済みの数列において中央に位置する値。要素数が奇数なら中央の1つ、偶数なら中央2つの平均値を取る。

```java
// 奇数個: [1, 3, 5] → 中央値は 3
// 偶数個: [1, 3, 5, 7] → 中央値は (3 + 5) / 2.0 = 4.0
```

### 二分探索（Binary Search）とは

ソート済みのデータに対して、探索範囲を毎回半分に絞ることでO(log n)で目的の値を見つける手法。`lo` と `hi` で探索範囲を管理し、中央の値を基準に範囲を狭めていく。

```java
int lo = 0, hi = n;
while (lo <= hi) {
    int mid = (lo + hi) / 2;       // 探索範囲の中央を計算する
    if (条件を満たす) { /* 答え */ }
    else if (midが大きすぎる) { hi = mid - 1; }  // 左半分に絞る
    else { lo = mid + 1; }                        // 右半分に絞る
}
```

### 番兵値（Sentinel Value）とは

配列の境界外アクセスを回避するために使う特別な値。`Integer.MIN_VALUE`（整数の最小値）と `Integer.MAX_VALUE`（整数の最大値）を使うことで、比較条件が境界ケースでも破綻しないようにする。

```java
Integer.MIN_VALUE;  // -2147483648 — どの要素よりも小さい値として使う
Integer.MAX_VALUE;  //  2147483647 — どの要素よりも大きい値として使う
```

## 計算量

| | 値 |
|---|---|
| Time | O(log(min(m, n))) — 短い方の配列に対して二分探索を行う |
| Space | O(1) — 変数のみを使用し、追加のデータ構造を作成しない |

## コード

```java
// 入力: 2つのソート済み整数配列 n1 と n2
// 出力: 2つの配列を合併した場合の中央値を double で返す
public double findMedian(int[] n1, int[] n2) {
    // 短い方の配列で二分探索するために、n1が長ければ入れ替えて再帰呼び出しする
    // こうすることで探索範囲を最小化し、O(log(min(m, n))) を実現する
    if (n1.length > n2.length)
        return findMedian(n2, n1);

    int m = n1.length, n = n2.length;
    // 左半分に入れる要素数。+1することで奇数のとき左半分が1つ多くなり、
    // 左半分の最大値がそのまま中央値になる
    int half = (m + n + 1) / 2;
    // cut1の探索範囲: 0（n1から1つも取らない）〜 m（n1を全部取る）
    int lo = 0, hi = m;

    while (lo <= hi) {
        // n1から左半分に入れる個数を二分探索の中央値で決める
        int cut1 = (lo + hi) / 2;
        // n2から左半分に入れる個数（左半分の合計がhalfになるよう自動決定）
        int cut2 = half - cut1;

        // n1の左半分の末尾（cut1=0なら左半分が空なので、
        // どの要素よりも小さい番兵値を使い、比較条件を常に成立させる）
        int l1 = cut1 == 0 ?
            Integer.MIN_VALUE :
            n1[cut1 - 1];
        // n2の左半分の末尾（cut2=0なら左半分が空なので番兵値を使う）
        int l2 = cut2 == 0 ?
            Integer.MIN_VALUE :
            n2[cut2 - 1];
        // n1の右半分の先頭（cut1=mなら右半分が空なので、
        // どの要素よりも大きい番兵値を使い、比較条件を常に成立させる）
        int r1 = cut1 == m ?
            Integer.MAX_VALUE :
            n1[cut1];
        // n2の右半分の先頭（cut2=nなら右半分が空なので番兵値を使う）
        int r2 = cut2 == n ?
            Integer.MAX_VALUE :
            n2[cut2];

        // 交差比較: 左半分の全要素 ≤ 右半分の全要素 なら正しい分割
        if (l1 <= r2 && l2 <= r1) {
            // 正しい分割が見つかった
            if ((m + n) % 2 == 1)
                // 奇数個: 左半分の最大値がそのまま中央値
                return Math.max(l1, l2);
            // 偶数個: 左半分の最大値と右半分の最小値の平均が中央値
            return (Math.max(l1, l2)
                + Math.min(r1, r2))
                / 2.0;
        } else if (l1 > r2) {
            // n1の左半分末尾がn2の右半分先頭を超えている → n1から取りすぎ → cut1を減らす
            hi = cut1 - 1;
        } else {
            // l2 > r1: n1から取らなすぎ → cut1を増やす
            lo = cut1 + 1;
        }
    }
    // 問題の制約上、正しい分割は必ず見つかるのでここには到達しない
    return -1;
}
```
