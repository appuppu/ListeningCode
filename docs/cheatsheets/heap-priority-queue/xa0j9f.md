# Tracking the Kth Largest Element in a Stream — ストリームからK番目に大きい要素を常に取得する

## 問題の本質

整数 `k` と初期の数値リストが与えられるクラスを設計する。`add` メソッドが呼ばれるたびに新しい数値をストリームに追加し、その時点でのストリーム全体の中で**K番目に大きい要素**を返す。

## 核心のアイデア

K番目に大きい要素だけが必要なので、上位K個の要素だけをMin-Heapで保持すれば、ヒープの根（最小値）が常にK番目に大きい要素になる。

## 思考プロセス

1. **必要なのはK番目に大きい要素だけである**: ストリーム全体をソートする必要はなく、上位K個の要素さえ把握していればK番目に大きい要素は確定する
2. **上位K個を効率的に管理したい**: 要素の追加と最小値の取り出しがO(log n)で行えるMin-Heap（最小ヒープ）が適している。Min-Heapの根は常にヒープ内の最小値を保持するため、サイズをKに保てば根がK番目に大きい要素になる
3. **ヒープのサイズをKに制限する方法**: 新しい要素を追加した後、ヒープのサイズがKを超えた場合は `poll()` で根（最小値）を取り除く。これにより、K番目に大きい要素より小さい値が自動的に排除され、常に上位K個だけが残る
4. **K番目に大きい要素の取得方法**: ヒープのサイズがちょうどKのとき、根の値がK番目に大きい要素である。`peek()` でO(1)で取得できる
5. **初期化時にもaddを再利用する**: コンストラクタで初期リストの各要素に対して `add` を呼び出せば、同じロジックでヒープを構築できる。初期化と追加でコードを共通化できる

## 前提知識

### Min-Heap（最小ヒープ）とは

ヒープは完全二分木の構造を持つデータ構造である。Min-Heapでは、親ノードの値が常に子ノードの値以下になるように維持される。そのため、根（ルート）には常にヒープ内の最小値が位置する。要素の追加と最小値の取り出しはO(log n)で行える。

### PriorityQueue とは

JavaにおけるMin-Heapの実装クラス。デフォルトでは要素を昇順（小さい順）に優先付けする。

```java
PriorityQueue<Integer> heap = new PriorityQueue<>();  // 空のMin-Heapを作成
heap.offer(5);        // 要素5をヒープに追加する
heap.offer(3);        // 要素3をヒープに追加する
heap.offer(8);        // 要素8をヒープに追加する
heap.peek();          // ヒープの根（最小値）を削除せずに返す → 3
heap.poll();          // ヒープの根（最小値）を削除して返す → 3
heap.size();          // ヒープ内の要素数を返す → 2
```

### なぜMin-HeapでK番目に大きい要素がわかるのか

サイズKのMin-Heapには上位K個の大きい要素が入っている。ヒープの根はその中で最も小さい値、つまり「上位K個の中の最小値」=「全体のK番目に大きい要素」である。
例: k=3, ヒープの中身が [4, 5, 8] のとき、根は4。これは全体で3番目に大きい要素である。

## 計算量

| | 値 |
|---|---|
| Time | O(log k) — addメソッド1回あたり、サイズKのヒープへの挿入と削除がそれぞれO(log k)で行われる |
| Space | O(k) — ヒープには常に最大K個の要素のみを保持する |

## コード

```java
// 入力: 整数 k、初期の整数配列 nums、および add メソッドに渡される整数 val
// 出力: add メソッドは、ストリーム全体でK番目に大きい要素を int で返す
class KthLargest {
    // Kはヒープのサイズ上限として使い続けるため、フィールドに保持する
    int k;
    // PriorityQueueはデフォルトでMin-Heap（最小値が根）として動作する
    PriorityQueue<Integer> heap;

    // コンストラクタ: kと初期配列を受け取り、ヒープを構築する
    KthLargest(int k, int[] nums) {
        this.k = k;
        heap = new PriorityQueue<>();
        // addメソッド内でヒープのサイズ制限が行われるため、初期化専用のロジックは不要
        for (int n : nums) {
            add(n);
        }
    }

    // 新しい値を追加し、K番目に大きい要素を返す
    int add(int val) {
        // ヒープの末尾に要素を挿入し、ヒープの性質を維持するよう親方向へ移動する（O(log k)）
        heap.offer(val);

        // サイズがKを超えた場合、K番目より小さい要素が1つ余分に存在している
        if (heap.size() > k) {
            // Min-Heapの根は常に最小値なので、削除されるのはK番目より小さい値である
            heap.poll();
        }

        // ヒープのサイズがちょうどKのとき、根はヒープ内の最小値 = 全体でK番目に大きい要素
        return heap.peek();
    }
}
```
