# Finding the Kth Largest Element in an Array — 未ソート配列からK番目に大きい要素を見つける

## 問題の本質

整数の配列 `nums` と整数 `k` が与えられる。配列をソートした場合に大きい方から数えて `k` 番目にあたる要素の値を返す。重複する値もそれぞれ独立にカウントする（k番目に大きい「異なる値」ではない）。

## 核心のアイデア

配列全体をソートしなくても、ピボットを基準に配列を分割すれば「ピボットが何番目に大きいか」が即座に分かる。ピボットの位置が `k-1` になるまで探索範囲を片側に絞り込むことで、平均O(n)で目的の要素にたどり着ける。

## 思考プロセス

1. **K番目に大きい要素はソート後のインデックスで決まる**: 配列を降順にソートすれば、インデックス `k-1` の要素が答えになる。しかし完全なソートはO(n log n)かかるので、もっと効率的な方法を考える
2. **必要なのはK番目の位置だけ**: 全体の順序は不要で、「K番目に大きい要素がどれか」だけ分かればよい。ピボットを使って配列を「ピボットより大きいグループ」と「ピボット以下のグループ」に分割すれば、ピボットが何番目に大きいかがその位置（インデックス）で分かる
3. **ピボットの位置で探索範囲を絞る**: partitionの結果、ピボットがインデックス `p` に置かれたとする。`p == k-1` なら答えが見つかる。`p < k-1` なら目的の要素はピボットより右側（より小さい側）にあるので、探索範囲を `p+1` 以降に絞る。`p > k-1` なら左側に絞る
4. **降順にpartitionする**: 通常のQuickSortのpartitionは昇順だが、「K番目に大きい」を求めるために降順にpartitionする。つまり、ピボットより大きい要素を左側に集める。こうすることで、インデックス `k-1` が答えの位置に対応する
5. **ループで片側だけを繰り返し処理する**: QuickSortは両側を再帰的に処理するが、Quickselectでは答えが含まれる片側だけを処理すればよい。whileループで `l <= r` の間、partitionを繰り返し、`p == k-1` になった時点でその要素を返す

## 前提知識

### Quickselect とは

QuickSortと同じpartition操作を使い、配列の中からK番目に小さい（または大きい）要素を平均O(n)で見つけるアルゴリズム。QuickSortが両側を再帰処理するのに対し、Quickselectは片側だけを処理するため、平均計算量がO(n)になる。

### partition（分割）とは

配列の中から1つのピボットを選び、ピボットより大きい要素を左側に、ピボット以下の要素を右側に移動させる操作。操作後、ピボットは最終的な正しい位置に置かれる。この位置（インデックス）がピボットの「順位」を表す。

```java
// 降順partition: ピボットより大きい要素を左側に集める
// 戻り値: ピボットが置かれたインデックス
int pivot = nums[r];       // 右端の要素をピボットに選ぶ
int store = l;             // 次にスワップする位置を指すポインタ
// nums[i] > pivot なら、nums[i]をstore位置にスワップしてstoreを進める
// 最後にpivotをstore位置に置く → storeがピボットの最終位置
```

### swap（要素の交換）とは

配列内の2つの要素の位置を入れ替える操作。一時変数 `temp` を使って値を退避させることで、上書きを防ぐ。

```java
int temp = nums[i];    // nums[i]の値を一時変数に退避する
nums[i] = nums[store]; // nums[store]の値をnums[i]に上書きする
nums[store] = temp;    // 退避しておいた元のnums[i]の値をnums[store]に書き込む
```

## 計算量

| | 値 |
|---|---|
| Time | O(n) 平均 — 毎回探索範囲が平均して半分になるため、n + n/2 + n/4 + ... ≈ 2n = O(n) |
| Space | O(1) — 配列をin-placeで操作し、追加のデータ構造を使わない |

## コード

```java
// 入力: 整数配列 nums と整数 k
// 出力: 配列の中でK番目に大きい要素の値を int で返す

// 降順partition: ピボットより大きい要素を左側に集め、ピボットの最終位置を返す
private int partition(int[] nums, int l, int r) {
    // 探索範囲の右端の要素をピボットとして選ぶ
    int pivot = nums[r];
    // storeは「次にピボットより大きい要素を置くべき位置」を指す
    int store = l;

    // l から r-1 まで走査し、ピボットより大きい要素を左側に集める
    for (int i = l; i < r; i++) {
        // 現在の要素がピボットより大きければ、store位置にスワップして左側に集める
        if (nums[i] > pivot) {
            int temp = nums[i];
            nums[i] = nums[store];
            nums[store] = temp;
            // storeを進めることで、次の大きい要素の配置先を更新する
            store++;
        }
    }

    // ピボットをstore位置に配置する（ピボットの最終的な正しい位置）
    // この時点で、storeより左にはピボットより大きい要素が、右にはピボット以下の要素がある
    int temp = nums[store];
    nums[store] = nums[r];
    nums[r] = temp;
    // storeがピボットの最終位置 = ピボットの「降順での順位」を表す
    return store;
}

public int findKthLargest(int[] nums, int k) {
    // 探索範囲を配列全体で初期化する
    int l = 0, r = nums.length - 1;

    // 探索範囲が有効な間、partitionを繰り返す。ループが回るたびに探索範囲が狭まる
    while (l <= r) {
        // 現在の探索範囲でpartitionを実行し、ピボットの位置を取得する
        int p = partition(nums, l, r);

        if (p == k - 1) {
            // ピボットがK番目に大きい位置にあるので答えを返す
            // 降順で左から数えてインデックス k-1 がK番目に大きい要素の位置
            return nums[p];
        } else if (p < k - 1) {
            // K番目はピボットより右側（より小さい側）にあるので、探索範囲の左端を縮める
            l = p + 1;
        } else {
            // K番目はピボットより左側（より大きい側）にあるので、探索範囲の右端を縮める
            r = p - 1;
        }
    }
    // 問題の制約上、有効な k が与えられるのでここには到達しない
    return -1;
}
```
