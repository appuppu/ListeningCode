# Scheduling Tasks With Cooldown Intervals — クールダウン付きタスクの最小実行時間を求める

## 問題の本質

タスクの配列（文字で表現）と非負整数 `n`（クールダウン間隔）が与えられる。同じタスクは最低 `n` 間隔空けないと再実行できない。クールダウン中はCPUがアイドル状態になる。すべてのタスクを完了するのに必要な**最小時間単位数**を返す。

## 核心のアイデア

最も頻度の高いタスクがスケジュール全体の骨格を決める。最頻タスクの間に生じるクールダウンの隙間を他のタスクで埋められるかどうかで、全体の時間が「数式による計算結果」か「タスク総数」の大きい方に決まる。

## 思考プロセス

1. **最頻タスクがボトルネックになる**: クールダウン制約が最も厳しいのは、出現回数が最も多いタスクである。このタスクが全体のスケジュールの長さを支配する
2. **最頻タスクを並べると隙間が生じる**: 最頻タスクの出現回数を `maxFreq` とすると、このタスクを `n` 間隔空けて並べたとき、タスク間に `(maxFreq - 1)` 個のブロックが生じる。各ブロックの長さは `(n + 1)`（タスク1つ＋クールダウン `n` スロット）である
3. **隙間を他のタスクで埋める**: 各ブロック内のクールダウンスロットに、他のタスクを配置してアイドル時間を減らす。隙間が全て埋まればアイドルは発生しない
4. **最後のブロックは特別扱いする**: 最後の実行にはクールダウンが不要なので、最後のブロックには最頻タスク（と同率のタスク）だけが入る。最頻と同じ回数を持つタスクの個数を `maxCount` とすると、最後のブロックの長さは `maxCount` である
5. **数式で全体の長さを計算する**: `(maxFreq - 1) * (n + 1) + maxCount` で、最頻タスクを軸にしたスケジュールの長さが求まる
6. **タスク総数との比較が必要**: 隙間が全て埋まり、さらにタスクが余る場合は、アイドルが一切不要でタスク総数がそのまま答えになる。よって最終的な答えは `Math.max(formulaResult, tasks.length)` である

## 前提知識

### 頻度配列とは

固定サイズの配列を使って、各文字の出現回数を数えるテクニック。英大文字のみの場合、サイズ26の配列で全文字をカバーできる。HashMapより高速かつ省メモリである。

```java
int[] freq = new int[26];            // A〜Zに対応する26個のカウンタを0で初期化
freq['B' - 'A']++;                   // 'B'の出現回数を1増やす（インデックス1）
freq['B' - 'A'];                     // 'B'の出現回数を取得する → 1
```

### Math.max とは

2つの値のうち大きい方を返すメソッド。2つの候補から答えを選ぶときに使う。

```java
Math.max(10, 7);    // → 10（大きい方を返す）
Math.max(5, 12);    // → 12
```

### この問題におけるブロック構造とは

最頻タスクを `A`（出現回数3）、`n = 2` とすると、スケジュールは以下のブロック構造になる：

```
[A _ _] [A _ _] [A]
 ブロック1  ブロック2  最後
```

`_` はクールダウンスロットで、他のタスクまたはアイドルが入る。最後のブロックにはクールダウンが不要なので `A` だけが入る。

## 計算量

| | 値 |
|---|---|
| Time | O(k) — タスク配列を1回走査し、固定長26の配列を定数回走査する（kはタスク数） |
| Space | O(1) — サイズ26の固定長配列のみ使用する |

## コード

```java
// 入力: 文字配列 tasks（各タスクは'A'〜'Z'の英大文字）と非負整数 n（クールダウン間隔）
// 出力: すべてのタスクを完了するのに必要な最小時間単位数を int で返す
public int leastInterval(char[] tasks, int n) {
    // サイズ26の頻度配列を作成する。freq[0]が'A'の回数、freq[1]が'B'の回数に対応する
    int[] freq = new int[26];
    // tasks を走査し、t - 'A' により文字を0〜25のインデックスに変換してカウントする
    for (char t : tasks)
        freq[t - 'A']++;

    // freq 配列を走査して最大の出現回数を求める。maxFreq はスケジュールのブロック数を決定する
    int maxFreq = 0;
    for (int f : freq)
        maxFreq = Math.max(maxFreq, f);

    // 出現回数が maxFreq と等しいタスクの個数を数える。maxCount は最後のブロックに入るタスクの数
    int maxCount = 0;
    for (int f : freq)
        if (f == maxFreq) maxCount++;

    // (maxFreq - 1): クールダウンが必要なブロックの数
    // (n + 1): 各ブロックの長さ（タスク1つ＋クールダウン n スロット）
    // maxCount: 最後のブロックの長さ（最頻タスクと同率のタスクのみ入る）
    int formulaResult =
        (maxFreq - 1) * (n + 1)
        + maxCount;

    // formulaResult はクールダウンによるアイドルが発生する場合の長さ
    // tasks.length はアイドルが一切不要な場合（隙間が全て埋まりタスクが余る場合）の長さ
    // 2つのうち大きい方が正しい答えになる
    return Math.max(formulaResult,
        tasks.length);
}
```
