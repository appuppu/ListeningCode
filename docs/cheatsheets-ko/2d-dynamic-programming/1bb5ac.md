# Maximizing Stock Profit With a Cooldown Period — 쿨다운이 있는 주식 거래에서 최대 이익을 구하기

## 문제의 본질

주가 배열 `prices`가 주어진다. 각 인덱스는 날짜를 나타낸다. 주식을 여러 번 매매할 수 있지만, 매도한 다음 날은 **쿨다운**으로 거래할 수 없다. 이 제약 조건 하에서 얻을 수 있는 **최대 이익**을 반환한다.

## 핵심 아이디어

각 날의 상태를 「주식을 보유 중(hold)」「매도 직후(sold)」「휴식 중(rest)」의 3가지로 분류하고, 전날의 3가지 상태에서 당일의 3가지 상태로의 전이를 정의한다. 각 날은 전날에만 의존하므로, 배열이 아닌 3개의 변수만으로 상태를 관리할 수 있다.

## 사고 과정

1. **각 날에는 3가지 상태가 있다**: 어떤 날의 종료 시점에서 자신은 「주식을 보유하고 있다(hold)」「그 날 매도했다(sold)」「아무것도 하지 않았다(rest)」 중 하나이다. 이 3가지 상태로 모든 경우를 포괄할 수 있다
2. **상태 간의 전이를 정의한다**: hold는 「전날도 hold로 아무것도 하지 않는다」 또는 「전날이 rest이고 오늘 매수한다」 중 큰 쪽이다. sold는 「전날이 hold이고 오늘 매도한다」이다. rest는 「전날도 rest로 아무것도 하지 않는다」 또는 「전날이 sold이고 쿨다운이 끝난다」 중 큰 쪽이다. 쿨다운 제약은 「sold 다음 날은 hold로 전이할 수 없다」는 규칙으로 자연스럽게 표현된다
3. **초기 상태를 설정한다**: 0일째에 매수하면 hold = -prices[0] (이익이 마이너스가 된다). 0일째에 매도하거나 휴식하는 것은 아직 불가능하므로, sold = Integer.MIN_VALUE (이 상태는 미도달을 의미한다), rest = 0 (아무것도 하지 않으면 이익은 0)으로 설정한다
4. **각 날은 전날의 상태에만 의존한다**: 전이식을 보면, 당일의 각 상태는 전날의 3가지 상태에서만 계산할 수 있다. 즉, 전체 날짜분의 배열을 가질 필요 없이, 3개의 변수를 매일 갱신하는 것만으로 충분하다
5. **동시 갱신이 필요하다**: 당일의 hold, sold, rest는 모두 전날의 값에서 계산하므로, 새로운 값을 임시 변수에 저장한 후 한꺼번에 전날의 변수를 덮어쓴다. 순차적으로 덮어쓰면, 아직 계산에 사용해야 할 전날의 값이 소실된다
6. **최종적으로 반환하는 것**: 마지막 날에 주식을 보유한 채로 끝나는 것은 최적이 아니므로, prevSold와 prevRest 중 큰 쪽이 최대 이익이다

## 사전 지식

### 상태 기계(State Machine)란

유한 개의 상태와 상태 간의 전이 규칙으로 구성되는 모델이다. 각 시점에서 반드시 하나의 상태에 있으며, 입력에 따라 다른 상태로 전이한다. 이 문제에서는 hold / sold / rest의 3가지 상태를 가진 상태 기계로 거래를 모델링한다.

```
rest ---(매수)---> hold
hold ---(매도)---> sold
sold ---(대기)---> rest (쿨다운)
hold ---(유지)---> hold
rest ---(유지)---> rest
```

### Math.max란

두 정수 중 큰 쪽을 반환하는 메서드이다. 상태 전이에서 여러 선택지가 있는 경우, 이익이 큰 쪽을 선택하기 위해 사용한다.

```java
Math.max(3, 7);    // → 7 (큰 쪽을 반환한다)
Math.max(-5, -2);  // → -2 (음수에서도 큰 쪽을 반환한다)
```

### Integer.MIN_VALUE란

Java의 int 타입이 가질 수 있는 최솟값(-2,147,483,648)이다. 「이 상태에는 아직 도달하지 않았다」는 것을 나타내기 위해 사용한다. 어떤 값과 비교해도 Math.max에서 선택되지 않으므로, 미도달 상태를 안전하게 무시할 수 있다.

```java
int x = Integer.MIN_VALUE;  // 아직 도달하지 않은 상태를 나타낸다
Math.max(x, 0);             // → 0 (미도달 상태는 선택되지 않는다)
```

## 계산량

| | 값 |
|---|---|
| Time | O(n) — 배열을 1회 순회하는 것만으로 충분하다 |
| Space | O(1) — 3개의 변수만으로 상태를 관리한다 |

## 코드

```java
// 입력: 정수 배열 prices (각 요소는 해당 날의 주가)
// 출력: 쿨다운 제약 조건 하에서 얻을 수 있는 최대 이익을 int로 반환한다
public int maxProfit(int[] prices) {
    int n = prices.length;
    // 주식을 매매하려면 최소 2일이 필요하다. n < 2이면 매매가 성립하지 않으므로 0을 반환한다
    if (n < 2) return 0;

    // 0일째의 각 상태를 초기화한다
    int prevHold = -prices[0];          // 0일째에 매수한 경우의 이익 (지출이므로 마이너스)
    int prevSold = Integer.MIN_VALUE;   // 0일째에 매도하는 것은 불가능하다 (미도달을 나타낸다)
    int prevRest = 0;                   // 아무것도 하지 않으면 이익은 0이다

    for (int i = 1; i < n; i++) {
        // 전날의 3가지 상태에서 당일의 3가지 상태를 계산한다
        // newHold: 「전날도 보유(prevHold)」 또는 「전날은 휴식이고 오늘 매수(prevRest - prices[i])」 중 큰 쪽
        // 주의: 「전날이 sold이고 오늘 매수」는 선택지에 없다. 이것이 쿨다운 제약을 표현하고 있다
        int newHold = Math.max(prevHold,
            prevRest - prices[i]);

        // newSold: 보유하고 있던 주식을 오늘 매도한다. sell은 hold에서만 전이할 수 있으므로 Math.max는 불필요하다
        int newSold = prevHold + prices[i];

        // newRest: 「전날도 휴식(prevRest)」 또는 「전날에 매도하고 쿨다운이 끝남(prevSold)」 중 큰 쪽
        int newRest = Math.max(prevRest,
            prevSold);

        // 모두 계산한 후 한꺼번에 갱신한다
        // 계산 도중에 전날의 값을 덮어쓰지 않기 위해, 3개의 새로운 값을 모두 구한 후에 대입한다
        prevHold = newHold;
        prevSold = newSold;
        prevRest = newRest;
    }
    // 마지막 날에 주식을 보유한 채로 끝나는 것(prevHold)은 이익을 확정할 수 없으므로 최적이 아니다
    // sold와 rest 중 큰 쪽이 최대 이익이다
    return Math.max(prevSold, prevRest);
}
```
