# Finding How Many Days Until a Warmer Temperature — 각 날로부터 다음으로 기온이 오르는 날까지의 일수를 구하기

## 문제의 본질

정수 배열 `temperatures`가 주어진다. 각 날에 대해, 그 날보다 기온이 높은 **미래의 날**이 며칠 후에 있는지를 계산하고, 결과를 배열로 반환한다. 미래에 기온이 높은 날이 존재하지 않는 경우, 그 날의 답은 `0`으로 한다.

## 핵심 아이디어

단조 감소 스택에 인덱스를 쌓아 가면, 스택에는 "아직 자신보다 따뜻한 날을 찾지 못한 날"만 남는다. 새로운 날의 기온이 스택 위의 날의 기온보다 높으면, 그 인덱스의 차이가 그대로 "대기 일수"가 된다.

## 사고 프로세스

1. **각 날에 대해 "다음으로 기온이 오르는 날"을 찾아야 한다**: 단순하게 생각하면 각 날에서 오른쪽 방향으로 선형 탐색하지만, 그렇게 하면 O(n²)이 된다. 각 날의 "미해결 상태"를 효율적으로 관리하는 구조가 필요하다
2. **"아직 답이 정해지지 않은 날"을 추적하고 싶다**: 배열을 왼쪽부터 순회할 때, 현재 날보다 기온이 높은 미래의 날을 아직 찾지 못한 날을 "미해결 날"로 보유해 두면, 새로운 날이 올 때 일괄적으로 해결할 수 있다
3. **미해결 날을 스택으로 관리한다**: 스택에 인덱스를 쌓아 간다. 새로운 날의 기온이 스택 위의 날의 기온보다 높으면, 그 미해결 날의 답이 확정된다. 스택은 항상 기온이 위에서 아래로 향해 단조 감소가 된다 (낮은 기온이 위에 쌓인다)
4. **답은 인덱스의 차이로 구할 수 있다**: 미해결 날 `j`가 현재 날 `i`에 의해 해결될 때, 대기 일수는 `i - j`이다. 이 차이를 결과 배열의 `j`번째에 저장한다
5. **각 요소는 최대 1회씩 push와 pop된다**: 스택으로의 push는 각 요소에서 1회, pop도 최대 1회이므로, while 루프를 포함한 전체 처리 횟수는 O(n)에 수렴한다

## 전제 지식

### Stack(스택)이란

후입선출(LIFO) 데이터 구조이다. 마지막에 추가한 요소를 가장 먼저 꺼낸다. Java에서는 `Stack<Integer>` 클래스를 사용한다.

```java
Stack<Integer> stack = new Stack<>();  // 빈 스택을 생성한다
stack.push(5);          // 스택의 맨 위에 5를 추가한다
stack.peek();           // 스택의 맨 위 요소를 꺼내지 않고 반환한다 → 5
stack.pop();            // 스택의 맨 위 요소를 꺼내서 반환한다 → 5
stack.isEmpty();        // 스택이 비어 있는지를 boolean으로 반환한다 → true
```

### 단조 스택(Monotonic Stack)이란

스택 내의 요소가 항상 단조 증가 또는 단조 감소 순서를 유지하도록 관리하는 스택이다. 본 문제에서는 **단조 감소 스택**을 사용한다. 새로운 요소를 추가하기 전에, 스택의 순서를 깨뜨리는 요소를 모두 pop하여 단조성을 유지한다. "다음으로 큰(작은) 요소를 찾는" 패턴에 적용할 수 있다.

```java
// 단조 감소 스택의 기본 패턴
// 스택 내의 기온은 아래에서 위로 향해 감소한다
// 예: 스택 바닥[75, 71, 69]위 ← 기온이 감소하고 있다
// 여기에 72가 오면, 69와 71을 pop하여 해결하고, [75, 72]가 된다
```

## 계산량

| | 값 |
|---|---|
| Time | O(n) — 각 요소는 스택에 push와 pop을 각각 최대 1회씩 수행하므로, 전체적으로 O(n)이다 |
| Space | O(n) — 스택에 최대 n개의 인덱스를 저장한다 |

## 코드

```java
// 입력: 정수 배열 temperatures (각 날의 기온)
// 출력: 각 날로부터 다음으로 기온이 오르는 날까지의 일수를 저장한 int[]를 반환한다
public int[] dailyTemperatures(int[] temperatures) {
    // 결과 배열을 생성한다 (Java에서 int[]의 초기값은 0이므로, 미래에 따뜻한 날이 없는 경우의 답 0이 기본으로 설정된다)
    int[] result = new int[temperatures.length];
    // 아직 따뜻한 날을 찾지 못한 날의 인덱스를 저장하는 스택
    // 기온 값이 아닌 인덱스를 저장하는 이유: 대기 일수 계산에 인덱스의 차이가 필요하며, 인덱스로부터 기온은 temperatures[index]로 참조할 수 있기 때문이다
    Stack<Integer> indexStack = new Stack<>();

    // 배열을 인덱스 i = 0부터 끝까지 하나씩 순회한다
    for (int i = 0; i < temperatures.length; i++) {
        // 현재 기온이 스택 위의 날의 기온보다 높은 동안, 미해결 날을 해결한다
        // 조건: 스택이 비어 있지 않음 그리고 현재 기온 > 스택 위의 인덱스가 가리키는 기온
        while (!indexStack.isEmpty() && temperatures[i] > temperatures[indexStack.peek()]) {
            // 스택의 맨 위 인덱스를 꺼낸다
            int stackTopIndex = indexStack.pop();
            // 대기 일수 = 현재 인덱스 - 기다리고 있던 날의 인덱스
            result[stackTopIndex] = i - stackTopIndex;
        }
        // while 루프 종료 후 (스택이 비었거나, 스택 위의 기온이 현재 기온 이상), 현재 인덱스를 스택에 추가한다
        // 이 시점에서 스택 내는 단조 감소 순서가 유지되고 있다
        indexStack.push(i);
    }

    // 스택에 남아 있는 인덱스는 "미래에 따뜻한 날이 존재하지 않았던 날"이다
    // 이 날들의 결과는 초기값 0 그대로이므로, 추가 처리는 불필요하다
    return result;
}
```
