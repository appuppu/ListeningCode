# Searching for a Target in a Sorted Array — 정렬된 배열에서 타겟의 위치를 찾기

## 문제의 본질

정렬된 정수 배열 `nums`와 정수 `target`이 주어진다. 배열에서 `target`과 일치하는 요소를 찾아 해당 **인덱스**를 반환한다. `target`이 배열에 존재하지 않는 경우 `-1`을 반환한다.

## 핵심 아이디어

배열이 정렬되어 있으므로, 중앙 요소와 타겟을 비교하는 것만으로 탐색 범위를 매번 절반으로 줄일 수 있다. 이를 통해 모든 요소를 확인하는 O(n)이 아니라 O(log n)으로 탐색을 완료할 수 있다.

## 사고 프로세스

1. **정렬되어 있다는 조건을 활용한다**: 배열이 정렬되어 있으므로, 임의의 위치의 요소를 보면 타겟이 그 왼쪽에 있는지 오른쪽에 있는지를 판정할 수 있다. 이 성질을 이용하면 탐색 범위를 매번 절반으로 줄일 수 있다
2. **탐색 범위를 두 개의 포인터로 관리한다**: 배열의 왼쪽 끝을 `left`, 오른쪽 끝을 `right`로 하는 두 개의 포인터로 탐색 범위를 표현한다. 초기 상태에서는 배열 전체가 탐색 범위이다
3. **중앙 요소와 타겟을 비교한다**: 탐색 범위의 중앙 인덱스 `mid`를 계산하고, `nums[mid]`와 `target`을 비교한다. 일치하면 `mid`가 답이다
4. **비교 결과에 따라 탐색 범위를 절반으로 줄인다**: `nums[mid] < target`이면 타겟은 중앙보다 오른쪽에 있으므로 `left = mid + 1`로 왼쪽 끝을 줄인다. `nums[mid] > target`이면 타겟은 중앙보다 왼쪽에 있으므로 `right = mid - 1`로 오른쪽 끝을 줄인다
5. **탐색 범위가 없어질 때까지 반복한다**: `left <= right`인 동안 탐색을 계속한다. `left > right`가 되면 탐색 범위가 비었다는 것을 의미하며, 타겟이 배열에 존재하지 않으므로 `-1`을 반환한다
6. **중앙 인덱스 계산에서 오버플로를 방지한다**: `mid = (left + right) / 2`로 하면 `left + right`가 정수의 최댓값을 초과할 가능성이 있다. `mid = left + (right - left) / 2`로 작성하면 오버플로를 회피할 수 있다

## 사전 지식

### Binary Search(이진 탐색)란

정렬된 배열에 대해 탐색 범위를 매번 절반으로 줄여 나감으로써 목적 요소를 효율적으로 찾는 알고리즘이다. 탐색 범위의 중앙 요소와 타겟을 비교하고, 일치하지 않으면 왼쪽 절반 또는 오른쪽 절반 중 하나를 버린다. 이를 반복함으로써 탐색 횟수가 O(log n)이 된다.

```java
// 배열의 길이가 8인 경우의 탐색 횟수
// 1회째: 8 → 4 (절반으로 줄임)
// 2회째: 4 → 2 (절반으로 줄임)
// 3회째: 2 → 1 (절반으로 줄임)
// 최대 3회 = log₂(8) = 3
```

### 중앙 인덱스의 계산

두 개의 포인터 `left`와 `right`의 중간 위치를 구한다. `(left + right) / 2`가 아니라 `left + (right - left) / 2`를 사용함으로써 `left + right`의 덧셈에 의한 정수 오버플로를 방지한다.

```java
int left = 0;
int right = 10;
int mid = left + (right - left) / 2;  // mid = 0 + (10 - 0) / 2 = 5
```

### while 루프의 조건 `left <= right`

`left <= right`는 탐색 범위에 요소가 1개 이상 남아 있다는 것을 의미한다. `left == right`일 때 탐색 범위에 요소가 1개만 남아 있으며, 이 요소도 확인할 필요가 있으므로 `<`가 아니라 `<=`를 사용한다.

```java
// left=3, right=3 일 때, nums[3]은 아직 미확인 상태이다
// left <= right 는 true이므로 nums[3]을 확인할 수 있다
// left < right 로 하면 false가 되어 nums[3]을 확인하지 않고 종료해 버린다
```

## 계산량

| | 값 |
|---|---|
| Time | O(log n) — 탐색 범위를 매번 절반으로 줄이므로 최대 log₂(n)회의 비교로 충분하다 |
| Space | O(1) — 포인터용 변수만 사용하며, 추가적인 데이터 구조는 불필요하다 |

## 코드

```java
// 입력: 정렬된 정수 배열 nums와 정수 target
// 출력: target과 일치하는 요소의 인덱스를 int로 반환한다. 존재하지 않는 경우 -1을 반환한다
public int binarySearch(int[] nums, int target) {
    // 탐색 범위의 왼쪽 끝과 오른쪽 끝을 초기화한다. 이 두 변수로 탐색 범위를 관리한다
    int left = 0;
    int right = nums.length - 1;

    // left <= right: 탐색 범위에 요소가 1개 이상 남아 있는 동안 반복한다
    // left > right 가 되면 탐색 범위가 비었으므로 루프를 빠져나온다
    while (left <= right) {
        // 주의: (left + right) / 2 로 하면 left + right 의 덧셈에서 정수 오버플로가 발생할 가능성이 있다
        // left + (right - left) / 2 로 작성하면 오버플로를 방지할 수 있다
        int mid = left
            + (right - left) / 2;

        // 중앙 요소가 타겟과 일치하면 인덱스를 반환한다
        if (nums[mid] == target) {
            return mid;
        }

        // 타겟이 중앙보다 크면 탐색 범위를 오른쪽 절반으로 줄인다
        // mid 자체는 이미 확인했으므로 mid + 1로 설정한다
        if (nums[mid] < target) {
            left = mid + 1;
        }
        // 타겟이 중앙보다 작으면 탐색 범위를 왼쪽 절반으로 줄인다
        // mid 자체는 이미 확인했으므로 mid - 1로 설정한다
        else {
            right = mid - 1;
        }
    }

    // 탐색 범위가 비었으므로 타겟은 배열에 존재하지 않는다
    return -1;
}
```
