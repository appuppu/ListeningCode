# Finding the Minimum in a Rotated Sorted Array — 회전된 정렬 배열에서 최솟값을 찾기

## 문제의 본질

오름차순으로 정렬된 고유한 정수 배열이 1회 이상 n회 이하 회전되어 있다. 이 회전된 배열에서 **최소 요소**를 찾아 반환한다. 회전이란 배열의 마지막 요소를 맨 앞으로 이동하는 연산이며, 원래의 정렬 순서가 중간에 "꺾이는" 피벗이 존재한다.

## 핵심 아이디어

회전된 정렬 배열에서 최솟값은 정렬 순서가 무너지는 "피벗" 위치에 있다. 중앙 요소와 오른쪽 끝 요소를 비교하면, 최솟값이 왼쪽 절반과 오른쪽 절반 중 어디에 존재하는지를 한 번의 비교로 판정할 수 있으며, 이진 탐색으로 O(log n)에 찾을 수 있다.

## 사고 프로세스

1. **최솟값은 피벗 위치에 있다**: 회전된 정렬 배열은 "큰 부분 수열"과 "작은 부분 수열"이라는 2개의 정렬된 부분으로 나뉜다. 최솟값은 "작은 부분 수열"의 맨 앞, 즉 피벗 위치에 존재한다. 이 피벗을 찾는 것이 문제의 본질이다
2. **선형 탐색이 아닌 이진 탐색을 사용하고 싶다**: 배열이 완전히 정렬되어 있지는 않지만, 2개의 정렬된 부분으로 나뉘어 있다는 구조가 있다. 이 구조를 활용하면 매번 절반을 버리는 이진 탐색을 적용할 수 있다
3. **중앙 요소와 오른쪽 끝 요소를 비교한다**: `nums[mid] > nums[right]`가 성립하는 경우, mid에서 right 사이에 피벗(정렬 순서의 붕괴)이 존재하므로 최솟값은 오른쪽 절반에 있다. 반대로 `nums[mid] <= nums[right]`인 경우, mid에서 right까지는 정렬되어 있으며 최솟값은 mid 이하(mid 자체를 포함)에 있다
4. **왼쪽 끝이 아닌 오른쪽 끝과 비교하는 이유**: 왼쪽 끝과 비교하면, 배열이 회전되지 않은 경우(전체가 정렬된 상태)에 올바르게 판정할 수 없다. 오른쪽 끝과 비교하면 회전 여부에 관계없이 최솟값의 위치를 정확히 좁힐 수 있다
5. **탐색 범위의 갱신 방법**: `nums[mid] > nums[right]`일 때, mid는 최솟값이 아님이 확정되므로 `left = mid + 1`로 설정한다. 그렇지 않을 때, mid가 최솟값일 가능성이 있으므로 `right = mid`로 설정한다(mid를 제외하지 않는다)
6. **루프의 종료 조건**: `left < right`인 동안 루프를 돌며, `left == right`가 된 시점에서 탐색 범위가 1개의 요소로 좁혀진다. 해당 요소 `nums[left]`가 최솟값이다

## 전제 지식

### 회전된 정렬 배열이란

오름차순 정렬 배열 `[1, 2, 3, 4, 5]`를 오른쪽으로 2회 회전하면 `[4, 5, 1, 2, 3]`이 된다. 배열은 2개의 정렬된 부분 수열 `[4, 5]`와 `[1, 2, 3]`으로 나뉘며, 그 경계가 피벗이다.

```
원래 배열:      [1, 2, 3, 4, 5]
2회 회전 후:    [4, 5, 1, 2, 3]
                     ↑ 피벗(최솟값)
```

### 이진 탐색의 기본 구조

탐색 범위를 매번 절반으로 좁혀서 O(log n)으로 목적 요소를 찾는 기법이다. left와 right라는 2개의 포인터로 탐색 범위를 관리하며, 중앙 요소를 기준으로 범위를 갱신한다.

```java
int left = 0;
int right = nums.length - 1;
int mid = left + (right - left) / 2;  // 오버플로를 방지하는 중앙값 계산
```

### `left + (right - left) / 2`란

중앙 인덱스를 계산하는 식이다. `(left + right) / 2`로도 같은 결과를 얻을 수 있지만, left와 right가 큰 값일 때 덧셈이 int의 최댓값을 초과할 가능성이 있다. 이 식은 그 **오버플로를 방지하는** 안전한 표기법이다.

## 계산량

| | 값 |
|---|---|
| Time | O(log n) — 매번 탐색 범위를 절반으로 좁히므로, 최대 log n번의 비교로 최솟값을 찾을 수 있다 |
| Space | O(1) — left, right, mid 3개의 변수만 사용하며, 추가적인 데이터 구조는 불필요하다 |

## 코드

```java
// 입력: 회전된 정렬된 고유한 정수 배열 nums
// 출력: 배열 내의 최솟값을 int로 반환한다
public int findMin(int[] nums) {
    // 탐색 범위의 양 끝을 초기화한다. 이 두 변수가 탐색 범위의 양 끝을 나타낸다
    int left = 0;
    int right = nums.length - 1;

    // left == right가 되면 탐색 범위가 1개의 요소로 좁혀지며, 해당 요소가 최솟값이다
    while (left < right) {
        // (left + right) / 2 대신 이 식을 사용하는 이유는 정수 오버플로를 방지하기 위해서이다
        int mid = left + (right - left) / 2;

        // 중앙 요소가 오른쪽 끝보다 큰 경우, mid와 right 사이에 피벗(정렬 순서의 붕괴)이 존재한다
        if (nums[mid] > nums[right]) {
            // 최솟값은 mid보다 오른쪽에 있다. mid는 오른쪽 끝보다 크므로 최솟값이 아니며, 제외할 수 있다
            left = mid + 1;
        } else {
            // mid에서 right까지는 정렬되어 있다. 최솟값은 mid 이하(mid 자체를 포함)에 있다
            // mid 자체가 최솟값일 가능성이 있으므로, mid를 탐색 범위에서 제외하지 않는다
            right = mid;
        }
    }

    // left == right가 되어 탐색 범위가 1개의 요소로 좁혀졌으므로, 해당 요소가 최솟값이다
    return nums[left];
}
```
