# Finding the Minimum Time to Swim Across a Grid — Encontrar o tempo mínimo para atravessar uma grade nadando

## Essência do problema

É dado um grid n×n onde cada célula contém um valor de elevação único de 0 a n²-1. É possível nadar de uma célula para uma célula adjacente (cima, baixo, esquerda, direita) somente quando o tempo atual é **maior ou igual à elevação de ambas as células**. O objetivo é encontrar o **tempo mínimo** necessário para ir do canto superior esquerdo (0,0) até o canto inferior direito (n-1,n-1). O tempo inicial é o valor de grid[0][0].

## Ideia central

O **valor máximo** de elevação das células percorridas em um caminho determina o tempo necessário para esse caminho. Ao usar um min-heap para explorar sempre "a célula alcançável que exige o menor tempo", o tempo no momento em que o destino é alcançado pela primeira vez é a solução ótima.

## Processo de raciocínio

1. **Reformular a condição de movimento**: Para mover da célula A para a célula B, é necessário que "tempo ≥ max(A, B)". Ou seja, o tempo necessário para todo o caminho do início ao destino é igual ao "valor máximo de elevação de todas as células no caminho". Portanto, o problema se reduz a "encontrar o caminho que minimiza a elevação máxima no caminho"
2. **Perceber a semelhança com o problema de caminho mínimo**: O Dijkstra convencional minimiza a **soma** dos pesos das arestas no caminho, mas neste problema o objetivo é minimizar o **valor máximo** de elevação no caminho. Ao usar o máximo em vez da soma, a estrutura do Dijkstra pode ser aplicada diretamente
3. **Expandir a partir da célula com menor tempo usando fila de prioridade**: O min-heap (PriorityQueue) armazena as células pelo "tempo necessário para alcançá-las". Ao expandir sempre a partir da célula com o menor tempo necessário, garante-se que o tempo no momento da primeira chegada a cada célula é ótimo
4. **Calcular o tempo necessário para as células adjacentes**: Quando o tempo necessário para a célula atual (r,c) é `time`, o tempo necessário para a célula adjacente (nr,nc) é calculado como `Math.max(time, grid[nr][nc])`. Isso ocorre porque o maior valor entre "a elevação máxima do caminho até aqui" e "a elevação da próxima célula" se torna o tempo necessário do novo caminho
5. **Evitar duplicatas com controle de visitados**: Uma célula retirada do min-heap tem seu tempo ótimo confirmado nesse momento. Ela é marcada no array de visitados `vis` para evitar reprocessamento da mesma célula. Esse é o mesmo conceito dos nós confirmados no Dijkstra
6. **Retornar imediatamente ao alcançar o destino**: Se a célula retirada do heap for (n-1, n-1), o `time` nesse momento é o tempo mínimo. Como o min-heap processa os tempos em ordem crescente, a primeira chegada ao destino é a solução ótima

## Conhecimentos prévios

### O que é PriorityQueue (min-heap)

É uma estrutura de dados que permite retirar elementos em ordem de prioridade. Por padrão, o menor valor tem a maior prioridade. Tanto a inserção quanto a remoção operam com complexidade O(log n). No algoritmo de Dijkstra, a PriorityQueue é usada para selecionar eficientemente "o nó não confirmado com o menor custo".

```java
// Cria um min-heap que ordena pelo elemento de índice 0 do int[] em ordem crescente
PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[0] - b[0]);
pq.offer(new int[]{5, 0, 0});   // Adiciona um elemento (O(log n))
pq.offer(new int[]{3, 1, 0});   // Adiciona um elemento
int[] min = pq.poll();          // Remove e retorna o menor elemento → {3, 1, 0}
boolean empty = pq.isEmpty();   // Verifica se a fila está vazia → false
```

### O que é a variação do algoritmo de Dijkstra

O algoritmo de Dijkstra convencional minimiza a **soma** dos pesos das arestas, mas neste problema o objetivo é minimizar o **valor máximo** de elevação no caminho. Basta alterar a fórmula de atualização de distância de `dist[next] = dist[cur] + weight` para `dist[next] = max(dist[cur], grid[next])`, e a corretude do Dijkstra (a propriedade de que o ótimo é confirmado no momento da remoção do min-heap) é preservada.

### Exploração de células adjacentes nas 4 direções

As células adjacentes (cima, baixo, esquerda, direita) de uma célula (r,c) no grid são enumeradas adicionando os vetores de direção `{{0,1},{0,-1},{1,0},{-1,0}}`. É feita a verificação de limites (0 ≤ nr < n e 0 ≤ nc < n), e somente as células válidas são processadas.

```java
int[][] dir = {{0,1},{0,-1},{1,0},{-1,0}};  // 4 direções: direita, esquerda, baixo, cima
for (int[] d : dir) {
    int nr = r + d[0];  // Linha da célula adjacente
    int nc = c + d[1];  // Coluna da célula adjacente
    if (nr >= 0 && nr < n && nc >= 0 && nc < n) {
        // (nr, nc) é uma célula adjacente válida
    }
}
```

## Complexidade

| | Valor |
|---|---|
| Time | O(n² log n) — Cada uma das n² células é inserida e removida do heap no máximo uma vez. Cada operação no heap custa O(log n²) = O(log n) |
| Space | O(n²) — O array de visitados e o heap armazenam no máximo n² células cada |

## Código

```java
// Entrada: array de inteiros n×n grid (cada célula contém um valor de elevação único de 0 a n²-1)
// Saída: retorna como int o tempo mínimo necessário para ir do canto superior esquerdo (0,0) ao canto inferior direito (n-1,n-1)
int swimInWater(int[][] grid) {
    int n = grid.length;
    // Array de visitados que controla se o tempo ótimo de cada célula já foi confirmado (vis[r][c] = true significa confirmado)
    boolean[][] vis = new boolean[n][n];
    // Min-heap que retira em ordem crescente de tempo necessário (elemento: {tempo, linha, coluna})
    // A função de comparação (a,b)->a[0]-b[0] garante a remoção em ordem crescente do elemento de índice 0 (tempo necessário)
    PriorityQueue<int[]> pq =
        new PriorityQueue<>(
            (a, b) -> a[0] - b[0]);
    // Adiciona o ponto de partida ao heap e marca como visitado
    // O elemento de índice 0 é o tempo necessário, o de índice 1 é a linha, o de índice 2 é a coluna
    pq.offer(new int[]
        {grid[0][0], 0, 0});
    vis[0][0] = true;
    // Vetores de direção para as 4 direções (cima, baixo, esquerda, direita)
    int[][] dir =
        {{0,1},{0,-1},{1,0},{-1,0}};
    while (!pq.isEmpty()) {
        // Remove a célula com o menor tempo necessário (pela propriedade do min-heap, o tempo ótimo é confirmado neste momento)
        int[] cur = pq.poll();
        int time = cur[0];
        int r = cur[1], c = cur[2];
        // Se o destino foi alcançado, esse tempo é a solução ótima (como os tempos são processados em ordem crescente, a primeira chegada é ótima)
        if (r == n-1 && c == n-1)
            return time;
        // Explora as células adjacentes nas 4 direções
        for (int[] d : dir) {
            int nr = r+d[0];
            int nc = c+d[1];
            // Processa apenas células dentro dos limites e não visitadas
            if (nr >= 0 && nr < n
                && nc >= 0 && nc < n
                && !vis[nr][nc]) {
                // Nota: marcar como visitado no momento da inserção no heap evita que a mesma célula seja adicionada ao heap múltiplas vezes
                vis[nr][nc] = true;
                // A elevação máxima no caminho determina o tempo necessário (o maior entre "a elevação máxima até aqui" e "a elevação da próxima célula")
                int nt = Math.max(
                    time,grid[nr][nc]);
                pq.offer(new int[]
                    {nt, nr, nc});
            }
        }
    }
    // Pelas restrições do problema, o grid é conexo, então este ponto nunca é alcançado
    return -1;
}
```
