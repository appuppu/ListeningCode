# Reconstruindo um Itinerário de Voo — Reconstruir o itinerário lexicograficamente menor a partir de passagens aéreas

## Essência do Problema

É fornecida uma lista de passagens aéreas representadas por pares de aeroporto de partida e aeroporto de chegada. O objetivo é reconstruir um itinerário que parta de JFK e utilize todas as passagens exatamente uma vez. Se existirem múltiplos itinerários válidos, deve-se retornar o menor em ordem lexicográfica.

## Ideia Central

Este é um problema de caminho euleriano, no qual se deve percorrer todas as arestas (passagens) exatamente uma vez. Se os destinos de cada aeroporto forem gerenciados com uma PriorityQueue, a ordem lexicográfica mínima é garantida automaticamente. Ao construir o itinerário de trás para frente com o algoritmo de Hierholzer, os becos sem saída são tratados corretamente.

## Processo de Raciocínio

1. **Usar todas as passagens exatamente uma vez = caminho euleriano**: Cada passagem é uma aresta de um grafo direcionado. O problema de encontrar um caminho que percorra todas as arestas exatamente uma vez se reduz ao problema do caminho euleriano (Eulerian Path)
2. **É necessário ordenar para garantir a ordem lexicográfica mínima**: Quando há múltiplos destinos a partir de um aeroporto, deseja-se escolher primeiro o menor em ordem lexicográfica. Armazenando os destinos de cada aeroporto em uma PriorityQueue (min-heap), basta chamar `poll()` para sempre obter o destino lexicograficamente menor
3. **Uma abordagem gulosa simples não lida com becos sem saída**: Se sempre se escolher o menor em ordem lexicográfica, pode-se chegar a um beco sem saída enquanto ainda restam arestas não utilizadas. Por exemplo, se existirem as passagens JFK→A→JFK→B, ao escolher A primeiro a partir de JFK, é possível seguir A→JFK→B; porém, ao escolher B primeiro, chega-se a um beco sem saída em B
4. **Construir de trás para frente com o algoritmo de Hierholzer**: No DFS, quando um nó não tem mais destinos (chega-se a um beco sem saída), ele é adicionado ao **início** da lista de resultados. Dessa forma, os becos sem saída são posicionados no final do itinerário, e as arestas restantes são adicionadas ao início na ordem correta durante o retrocesso da recursão
5. **Funcionamento do DFS recursivo**: A partir do nó atual, extrai-se o destino lexicograficamente menor da PriorityQueue e executa-se o DFS recursivamente. Quando não há mais destinos, o nó atual é adicionado ao início da lista de resultados. Utilizando `addFirst` de LinkedList, a inserção no início é feita em O(1)
6. **O que é retornado no final**: Após a conclusão de todo o DFS, a lista de resultados (LinkedList) é retornada diretamente. A lista contém o itinerário lexicograficamente menor começando por JFK

## Conhecimentos Prévios

### O que é PriorityQueue (fila de prioridade)

Uma estrutura de dados que ordena os elementos automaticamente ao adicioná-los e sempre retorna o menor elemento ao extrair. Internamente é implementada como um heap, e tanto a adição quanto a extração operam em O(log n).

```java
PriorityQueue<String> pq = new PriorityQueue<>();  // Cria um min-heap com a ordem natural das strings (ordem lexicográfica)
pq.offer("SFO");       // Adiciona "SFO"
pq.offer("ATL");       // Adiciona "ATL"
pq.poll();             // Extrai e remove o menor elemento "ATL" → "ATL"
pq.isEmpty();          // Retorna um boolean indicando se a fila está vazia → false ("SFO" ainda permanece)
```

### O que é computeIfAbsent

Um método que, somente quando a chave não existe no HashMap, gera um valor com a função especificada, registra-o e o retorna. Se a chave já existir, retorna o valor existente sem alteração. Permite escrever em uma linha os três passos de chamar `get`, verificar `null` e chamar `put`.

```java
Map<String, PriorityQueue<String>> graph = new HashMap<>();
// Se a chave "JFK" não existir, cria uma nova PriorityQueue, registra-a e a retorna
graph.computeIfAbsent("JFK", k -> new PriorityQueue<>()).offer("SFO");
// Como a chave "JFK" já existe, retorna a PriorityQueue existente (não cria uma nova)
graph.computeIfAbsent("JFK", k -> new PriorityQueue<>()).offer("ATL");
```

### O que é addFirst de LinkedList

Um método que adiciona um elemento ao início da lista em O(1). Diferentemente do `add` convencional (adição ao final), permite inserir no início sem deslocar os elementos existentes para trás. É utilizado para construir o resultado em ordem inversa no algoritmo de Hierholzer.

```java
LinkedList<String> result = new LinkedList<>();
result.addFirst("JFK");   // result: ["JFK"]
result.addFirst("ATL");   // result: ["ATL", "JFK"]
result.addFirst("SFO");   // result: ["SFO", "ATL", "JFK"]
```

### O que é o algoritmo de Hierholzer

Um algoritmo para encontrar um caminho euleriano (um caminho que percorre todas as arestas exatamente uma vez). Ele avança consumindo arestas via DFS e, ao chegar a um beco sem saída, adiciona o nó ao início do resultado. Após utilizar todas as arestas, a lista de resultados contém o caminho euleriano na ordem correta. O fato de posicionar naturalmente os becos sem saída no final do itinerário torna este algoritmo adequado para este problema.

## Complexidade

| | Valor |
|---|---|
| Time | O(E log E) — Cada passagem (aresta) tem custo de log E ao ser adicionada e extraída da PriorityQueue |
| Space | O(V + E) — Todas as arestas são armazenadas na lista de adjacência do grafo, e a pilha de recursão pode ter profundidade máxima igual ao número de arestas |

## Código

```java
// Entrada: lista de passagens aéreas tickets (cada passagem é um par de strings [aeroporto de partida, aeroporto de chegada])
// Saída: retorna o itinerário lexicograficamente menor começando por JFK como List<String>
public List<String> findItinerary(List<List<String>> tickets) {
    // Chave=aeroporto de partida, Valor=PriorityQueue que gerencia os aeroportos de chegada em ordem lexicográfica
    // Ao usar PriorityQueue, a extração sempre retorna o destino lexicograficamente menor
    Map<String, PriorityQueue<String>> graph = new HashMap<>();

    // Constrói o grafo a partir de todas as passagens
    // Com computeIfAbsent, se a chave src aparecer pela primeira vez, cria uma nova PriorityQueue; se já existir, obtém a existente
    for (List<String> t : tickets) {
        graph.computeIfAbsent(t.get(0), k -> new PriorityQueue<>())
             .offer(t.get(1));
    }

    // LinkedList para armazenar o resultado (usa addFirst para inserção em O(1) no início)
    LinkedList<String> result = new LinkedList<>();

    // Inicia o DFS a partir de JFK
    dfs("JFK", graph, result);
    return result;
}

void dfs(String curr,
          Map<String, PriorityQueue<String>> graph,
          LinkedList<String> result) {
    // Obtém a PriorityQueue de destinos acessíveis a partir do aeroporto atual
    PriorityQueue<String> dests = graph.get(curr);

    // Enquanto existirem destinos, extrai o lexicograficamente menor e executa o DFS
    // Nota: poll() remove o elemento, portanto a mesma aresta (passagem) nunca é percorrida duas vezes
    while (dests != null && !dests.isEmpty()) {
        dfs(dests.poll(), graph, result);
    }

    // Ao chegar a um beco sem saída, adiciona o aeroporto atual ao início da lista de resultados
    // Ao adicionar ao início, os nós de beco sem saída são posicionados no final do itinerário,
    // e os nós adicionados posteriormente são posicionados corretamente no início do itinerário
    result.addFirst(curr);
}
```
